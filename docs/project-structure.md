# Структура проекта

Документ описывает текущую структуру исходников. Версия приложения и параметры упаковки задаются в `package.json`; версии зависимостей закреплены в `package-lock.json`.

```text

    index.js                       Главный процесс Electron: окна, трей, IPC, интеграции
    hardware-acceleration.js        Чтение настройки GPU до готовности Electron
    open-audio-files.js             Пути из argv и очередь до готовности интерфейса
    system-integration.js           Linux .desktop, MIME и настройки Windows
    cache/
      cover-cache-location.js      Выбор папки кэша обложек
      waveform-cache.js            Компактный дисковый кэш waveform
    integrations/
      lastfm/cover-service.js      Поиск обложек, загрузка и кэш локальных треков
      lrclib/lyrics-service.js     Получение текстов, разбор LRC и сетевые повторы
  preload/
    index.js                       API window.noctune, файлы и метаданные аудио
    artwork.js                     Уменьшение обложек и последовательная очередь
  renderer/
    index.html                     Интерфейс и порядок загрузки скриптов

                                   drag-drop.js — перетаскивание в музыкальный плейлист
    integrations/                  Тексты, обложки и поиск радиостанций

  renderer/                       Воспроизведение, радио, тексты, waveform и FPS
  structure/                      Пути модулей и ресурсов, синтаксис renderer
```

## Процессы и ответственность модулей

Установка расширений, подписи, версии, хранение и сетевой брокер находятся в
`src/main/addons/`. Изолированное исполнение и SDK — в `src/renderer/addons/`,
вкладка настроек — в `src/renderer/ui/addon-settings.js`. Примеры и схема manifest
хранятся в `addons/`; исходники расширений, примеры и инструменты SDK не включаются
в production-пакет. Подписанный каталог `addons/catalog/official.json` входит
в приложение для работы магазина без сети. Расширения устанавливаются отдельно.
Декларации SDK находятся в `addons/sdk.d.ts`. [Формат расширений](extensions-api-v1.md).

`npm start` запускает `src/main/index.js`. Главное окно загружает `src/renderer/index.html`; системные API доступны интерфейсу через мост `window.noctune` из `src/preload/index.js`.

- **Main** управляет окнами, треем, обновлениями, Discord/Last.fm, сетевым получением текстов и обложек, дисковыми кэшами и настройкой аппаратного ускорения.
- **Preload** публикует разрешённые операции через `contextBridge`, читает файлы и метаданные, уменьшает обложки через `nativeImage`. Очередь ограничивает одновременную обработку; обложка активного трека получает приоритет.
- **Renderer** управляет интерфейсом и звуком через Web Audio API. Waveform строится отдельно от воспроизведения и хранится в компактном виде. Лимит FPS применяется к циклам эффектов, а прежний флаг `_rafSuspended` приостанавливает отрисовку при сворачивании в трей.

У главного окна включены `contextIsolation` и отключён `nodeIntegration`. `sandbox` отключён для preload, поскольку он использует Node.js для чтения файлов и метаданных. Изоляция контекста не означает, что preload работает в песочнице.

`src/web/redirect.html` публикуется отдельно от интерфейса приложения и обрабатывает переходы по ссылкам `noctune://`.

## Порядок загрузки renderer

Скрипты renderer подключаются обычными `<script>` и используют общие функции и состояние; это не независимые ES-модули. Источник актуального порядка — `src/renderer/index.html`.

1. В `<head>`: Lucide и `core/polyfill.js`.
2. После разметки: `core/dom-refs-state.js`, `core/effects-performance.js`, уведомления.
3. Фон, конфетти и фейерверки; затем управление воспроизведением, эквалайзер и плейлисты.
4. Waveform, общие обработчики перемотки (`playback/seek-controls.js`) и аудиодвижок; интерфейс текста, горячие клавиши и радио.
5. Хост сцен, визуализатор, `core/bootstrap.js`, основные настройки и настройки сцен.
6. Общие контракты расширений, API плеера, провайдеры, хост SDK и интерфейс расширений.
7. Настройки производительности и системной интеграции, импорт/экспорт плейлистов и интерфейс обновлений.

При добавлении или переносе скрипта сохраняйте зависимости этого порядка. Например, `requestEffectsFrame` должен существовать до запуска циклов эффектов, а DOM — до инициализации элементов интерфейса.

## Хранение данных и кэши

| Данные | Расположение и срок жизни |
|---|---|
| Настройки, плейлисты, состояние, сессия Last.fm | `config.json` в каталоге Electron `userData`, через `electron-store` |
| Waveform на диске | `userData/waveforms/*.bin`; 200 байт пиков на файл, до 1000 записей, без учёта накладных расходов файловой системы |
| Waveform в памяти | До 60 записей с компактными пиками; полный декодированный аудиобуфер не сохраняется в кэше |
| Обложки локальных треков Last.fm | Кэш приложения, подпапка папки с музыкой либо выбранный каталог; настраиваемый лимит 10–300 МБ |
| Обложки радио | Текущая композиция в памяти; постоянный кэш обложек обходится |
| Тексты LRCLIB | Кэш main-процесса в памяти, до 200 записей; сбрасывается при завершении процесса |
| Миниатюры плейлиста | Изображения до 96 px; большая встроенная обложка активного трека извлекается отдельно, до 1024 px |

Путь `userData` определяется Electron для платформы и установленного приложения. Waveform проверяется по абсолютному пути, размеру и времени изменения аудиофайла; смена этих данных приводит к новому ключу кэша. Декодирование выполняется последовательно с частотой 8000 Гц; устаревшие задания не заменяют waveform текущего трека.

Настройка аппаратного ускорения читается синхронно до `app.whenReady()`. Изменение записывается в конфигурацию и требует перезапуска; переключение FPS применяется сразу.

## Запуск и упаковка

```bash
npm ci
npm start
npm run dist
```

`npm ci` устанавливает зависимости по lockfile. `npm run dist` запускает `electron-builder` для текущей платформы и сохраняет артефакты в `dist/`. Конфигурация содержит NSIS для Windows и AppImage, pacman, tar.gz для Linux. Сборки проверяются в соответствующей среде.

Для Linux-пакета pacman требуется контакт сборщика: в `package.json` не задан
email автора. Передайте имя и email через параметр `linux.maintainer`, заменив
пример своими данными:

```bash
npm run dist -- --linux pacman --publish never '-c.linux.maintainer=Maintainer <maintainer@example.com>'
```

В пакет включаются только исполняемые модули и ресурсы приложения, production-зависимости, встроенные темы и обои. Подробности и аудит архива описаны в разделе [«Состав приложения при сборке»](#состав-приложения-при-сборке).

## Проверки

Контракт тем v1 описан в [themes-api-v1.md](themes-api-v1.md), API тем v2 — в [themes-api-v2.md](themes-api-v2.md). Обе версии используют `src/renderer/effects/scene-host.js` и версионированный `scene-sdk.js`; TypeScript-декларации v2 находятся в `themes/sdk.d.ts`. Валидатор и упаковщик в `src/main/scene-themes.js` выбирают версию из пакета. Эталон v2 находится в `themes/examples/api-v2`, готовый контейнер — в `themes/packages/api-v2-demo.noctheme`.

```bash
npm test
```

`tests/run.cjs` последовательно запускает файлы `.cjs` из `tests/main`, `tests/renderer` и `tests/structure`, останавливаясь при первой ошибке. Проверки включают кэширование, сетевые ошибки и отмену запросов, метаданные радио, переключение треков, миниатюры, память waveform, настройки GPU/FPS и связи файлов проекта. Проверки renderer используют изолированные сценарии Node.js; они не заменяют проверку интерфейса в Electron.

Отдельные сценарии настоящего Electron запускаются вручную. В PowerShell:

```powershell
.\node_modules\.bin\electron.cmd tests/native-addons-probe.cjs
```

В Linux:

```bash
./node_modules/.bin/electron tests/native-addons-probe.cjs
```

Для этих сценариев нужна среда с графическим дисплеем. Используются тестовые профили, временные данные и подставные ответы сервисов. Проверка расширений охватывает согласие на установку, изоляцию, настройки SDK, аудиопоток и освобождение ресурсов. Полный список проверок и команд запуска находится в [tests/README.md](../tests/README.md).


## Состав приложения при сборке

`build.files` в `package.json` перечисляет исполняемые модули main/preload,
HTML/CSS/JS интерфейса, общие runtime-модули и стили контролов
(`src/shared/settings-controls.css`), подписанный каталог магазина
(`addons/catalog/official.json`), встроенные сцены и их слои,
встроенные обои, иконки и лицензию. Electron-builder добавляет production-зависимости.
Декларации типов находятся в `addons/sdk.d.ts` и `themes/sdk.d.ts`; документация,
примеры, упаковщики и локальная веб-страница перенаправления остаются в репозитории.

Из зависимостей исключены source map, TypeScript-исходники, документация,
примеры, тесты и скрипты разработки. Для Lucide используется только
`dist/umd/lucide.min.js`. Лицензии и уведомления сторонних библиотек сохраняются.
`scene-sdk.js` входит в runtime: без него не работают встроенные и импортированные темы.

После сборки проверьте реальное содержимое архива:

```bash
npm run audit:package -- dist/linux-unpacked/resources/app.asar
```

Для Windows укажите `dist/win-unpacked/resources/app.asar`.
Проверка контролирует отсутствие файлов разработки, ссылки HTML и JS,
ресурсы встроенных тем, обои, зависимости и лицензию.

Интеграционную проверку расширений можно выполнить с модулями собранного архива:

```bash
./node_modules/.bin/electron tests/native-addons-probe.cjs --app-asar=dist/linux-unpacked/resources/app.asar
```
