# API расширений Noctune · v1

Расширения устанавливаются в **Настройки → Расширения** из `.noctaddon` или
по HTTPS-ссылке на подписанный пакет. Установка сначала показывает описание,
автора и разрешения. Новое расширение нужно отдельно включить в карточке.
Подтверждение открывается в отдельном окне, как при установке интерактивной темы.
В списке разрешений рядом с пояснением указано системное имя в квадратных скобках;
новые права и домены при обновлении выделены отдельно.
Встроенные Last.fm, Discord и LRCLIB остаются частью приложения.

Во вкладке доступны команды расширения, выключение, проверка обновлений,
возврат предыдущей версии и удаление вместе с данными. Установка новой версии
из файла тоже считается обновлением, если совпадает ID и издатель.
Кнопка «Магазин расширений» открывает отдельное окно с официальным каталогом
GitHub и заглушкой пользовательского каталога. Установка по введённой вручную
ссылке принимает непосредственно пакет, а не HTML-страницу релиза.
Порядок распространения и требования к заявкам описаны в
[публикации расширений](extensions-publishing.md).

## Структура проекта расширения

```text
my-addon/
  manifest.json
  main.js
  assets/
    defaults.json
  README.md
```

`manifest.json` описывает пакет, `entry` указывает входной скрипт. Допускаются
текстовые `.js`, `.json`, `.txt`, `.md`, изображения, шрифты
и аудиоресурсы (полный список ниже). Все файлы собираются в JSON-контейнер,
без ZIP и извлечения произвольных путей. Символические ссылки запрещены.
Максимум: 16 МБ контейнер, 32 файла, 512 КБ на текстовый файл и 2 МБ на
двоичный ресурс, четыре уровня папок.
Одновременно можно установить до 32 расширений.
Текстовые файлы читаются через `api.readText()`, двоичные — через `api.assets`. JavaScript нужно собрать в один входной
файл: загрузчика npm/CommonJS/ES-модулей в SDK 1 нет.

Пример: [track-info](../addons/examples/track-info/manifest.json).
Соберите демонстрационный пакет из исходников: `node scripts/pack-addon.cjs addons/examples/track-info addons/packages/track-info-demo.noctaddon`.
Каталог `addons/packages/` содержит локальные результаты сборки и исключён из Git.
Схема для редакторов: [manifest.schema.json](../addons/manifest.schema.json).
Окончательную проверку, включая существование файлов и совместимость версий,
выполняет установщик.

```json
{
  "id": "my-addon",
  "name": "Название расширения",
  "description": "Что добавляет расширение",
  "author": "Автор",
  "version": "1.0.0",
  "revision": 1,
  "apiVersion": 1,
  "minNoctuneVersion": "1.4.0",
  "type": "extension",
  "entry": "main.js",
  "permissions": ["storage.read", "storage.write", "notifications.show"],
  "commands": [{ "id": "show-message", "title": "Показать сообщение" }]
}
```

- `id`: постоянный ID из 2–64 символов, строчные латинские буквы, цифры и дефис;
  первый символ — буква. `constructor` и `prototype` зарезервированы.
- `version`: `x.y.z`, допускается prerelease. `revision` — положительное целое,
  строго увеличивается при каждом выпуске независимо от отображаемой версии.
- `apiVersion`: версия SDK, сейчас `1`; неизвестный API отклоняется до установки.
- `minNoctuneVersion`, необязательный `maxNoctuneVersion`: включительные границы.
- `type`: `extension` или `integration`. Сейчас это категория, а не дополнительные
  права: интеграции исполняются с той же изоляцией.
- `permissions`: только перечисленные ниже разрешения. Неизвестные поля и права
  отклоняются, новые права и домены явно отмечаются при обновлении.
- `commands`: до 12 кнопок в карточке. Обработчики регистрируются через SDK.
- `homepage`: необязательная HTTPS-ссылка автора.
- `update`: необязательные `{ "url": "https://host/release.json", "channel": "stable" }`.
  Не является обязательным условием установки; неподписанные пакеты обновляются из файла.

## Исполнение и SDK

Входной файл вызывает `NoctuneAddon.define(activate)`. Асинхронная `activate`
выполняется при включении и регистрирует обработчики. При выключении, обновлении
или удалении среда уничтожается. После следующего запуска плеера включённые
расширения запускаются снова. Ограничения: 10 секунд на запуск, 20 секунд на запрос SDK (OAuth — до 5 минут), до 5 минут на
команду, до 40 запросов SDK в секунду; зависшие Worker останавливаются.

```js
NoctuneAddon.define(api => {
    api.onCommand('show-message', async () => {
        const count = (await api.storage.get('count') || 0) + 1;
        await api.storage.set('count', count);
        await api.notify(`Запусков: ${count}`);
    });
});
```

| Разрешение | API | Границы |
| --- | --- | --- |
| `storage.read`, `storage.write` | `api.storage.get(key)`, `set(key, value)` | JSON, 128 КБ на расширение; собственное пространство ключей |
| `notifications.show` | `api.notify(text)` | Текст, 500 символов, раз в три секунды; соблюдается настройка уведомлений плеера |
| `playback.read` | `api.player.current()` | Название, исполнитель, позиция, playing/radio; без путей к файлам и доступа к медиатеке |
| `network.request` | `api.network.text(url)`, `json(url)` | GET-сокращения для HTTPS-origin из `network.origins`, до 1 МБ; три параллельных запроса |

Без разрешений доступны `api.version`, `api.manifest`, `api.onCommand()` и
`api.readText(file)`, `api.assets.read(file)` и `api.assets.url(file)`. Типы: [sdk.d.ts](../addons/sdk.d.ts).

Сетевое разрешение требует `"network": { "origins": ["https://api.example.com"] }`.
Редиректы проверяются повторно. Локальные, приватные и служебные адреса, HTTP,
пароли в URL и нестандартные порты не допускаются. DNS-адрес проверяется и
фиксируется на соединение; некоторые IPv6 transition/специальные диапазоны
консервативно отклоняются. Ответ должен быть несжатым текстом; клиент запрашивает
`Accept-Encoding: identity`. Таймаут HTTP — 15 секунд. Используется сетевой стек
Node.js; настройки прокси Chromium не переносятся автоматически.

### CDN и группы поддоменов · Noctune 1.4.0+

Кроме точного origin разрешена декларация `https://*.cdn.example.com`.
Она охватывает `a.cdn.example.com` и `a.b.cdn.example.com`, но не сам
`cdn.example.com`, `evilcdn.example.com` или `a.cdn.example.com.evil.org`.
Если нужен основной домен, перечислите его отдельно. До восьми деклараций,
а не восьми фактических серверов. Это общий механизм, без списка музыкальных
сервисов в плеере. Установщик явно показывает область поддоменов; переход
с точного origin на wildcard требует подтверждения нового сетевого доступа.

```json
"minNoctuneVersion": "1.4.0",
"network": {
  "origins": ["https://api.example.com", "https://*.cdn.example.com"],
  "routes": [
    {"origin":"https://api.example.com","path":"/resolve","methods":["GET"]},
    {"origin":"https://*.cdn.example.com","path":"/audio/","prefix":true,"methods":["GET","HEAD"]}
  ]
}
```

Wildcard допускается только как единственная левая метка `*.` перед DNS-доменом
из двух и более меток. Нельзя объявить все сайты `https://*`, весь TLD
`https://*.com`, wildcard для IP, порт, путь или `*` посередине имени.
Шаблоны канонические: HTTPS, ASCII/punycode, строчные буквы, без завершающей точки.
Область может охватывать независимо управляемые поддомены, поэтому выбирайте
узкий CDN-домен, которым доверяете, а не общий хостинг или публичный суффикс.
Worker передаёт в запросе фактический URL без `*`; брокер проверяет HTTPS,
домен, маршруты и публичный DNS с фиксацией адреса при каждом redirect.
Те же правила действуют для `network.text/json`, `network.request`, потоков,
HEAD и Range. Wildcard не разрешает локальные адреса или обход маршрутов.

**OAuth `resourceOrigins` и `credentials.origins` принимают только точные origin,**
явно перечисленные в `network.origins`. Шаблон CDN не даёт права передавать туда
токен. При смене origin на redirect авторизация и остальные пользовательские
заголовки снимаются, даже если оба сервера относятся к одной группе поддоменов.

Код работает в Worker непрозрачного sandbox-iframe, без Node, DOM, Electron
и прямого доступа к сети. Сеть и хранение обслуживает брокер в main, повторно
проверяющий актуальную версию и разрешения. Скрипт не загружается через require
в основном процессе. Изоляция ограничивает доступ к данным, но не гарантирует
жёсткую квоту памяти для произвольного JavaScript.

## Упаковка и подпись

Локальный пакет без подписи для разработки:

```bash
node scripts/pack-addon.cjs addons/examples/track-info /tmp/track-info.noctaddon
```

Для сетевой установки и обновлений нужен Ed25519. Закрытый ключ хранится
вне папки расширения и репозитория:

```bash
node scripts/create-addon-key.cjs /secure/location/publisher.pem
node scripts/pack-addon.cjs my-addon /tmp/my-addon.noctaddon --key /secure/location/publisher.pem
node scripts/create-addon-release.cjs /tmp/my-addon.noctaddon https://host/my-addon.noctaddon /secure/location/publisher.pem /tmp/release.json
```

Контейнер: `format: noctune-addon`, `formatVersion: 1`, `manifest`, `files`
(относительный путь → UTF-8 строка или `{encoding:"base64",data:"…"}` для
двоичных ресурсов SDK 1), необязательный `signature`.
Подпись: `{ algorithm: "Ed25519", publicKey: "base64 SPKI DER", value: "base64" }`.
Подписывается UTF-8 канонического JSON без корневого `signature`: ключи объектов
сортируются, массивы сохраняют порядок, пробелы не добавляются.

Первый пакет закрепляет отпечаток ключа издателя за ID. Самоподпись подтверждает
целостность и последующие выпуски, но не реальную личность автора. Установщик
показывает это различие и запрашивает доверие. Смена ключа и переход подписанного
пакета на неподписанный блокируются. Для смены издателя нужна новая установка
после удаления; автоматическая ротация ключей в API 1 отсутствует.

Официальные расширения с доверенной подписью Noctune также обновляются через
подписанный каталог магазина без собственного `manifest.update` и `release.json`.
Для этого пакеты размещаются в основном репозитории; порядок описан в
[публикации расширений](extensions-publishing.md#официальные-расширения-из-основного-репозитория).

Для собственного канала обновлений `release.json` имеет формат:

```json
{
  "format": "noctune-addon-release",
  "formatVersion": 1,
  "id": "my-addon",
  "version": "1.1.0",
  "revision": 2,
  "channel": "stable",
  "packageUrl": "https://host/my-addon-1.1.0.noctaddon",
  "sha256": "SHA-256 точных байтов опубликованного файла",
  "signature": { "algorithm": "Ed25519", "publicKey": "...", "value": "..." }
}
```

Release и пакет подписываются одним ключом. Проверяются ID, версия, ревизия,
канал и хеш. Пакет после создания release нельзя переформатировать: изменятся
точные байты и SHA-256. Публикуйте файл пакета первым, release — последним.
Noctune проверяет обновления по кнопке и всегда показывает их перед установкой;
новые права не предоставляются молча. Максимум release — 64 КБ.

## Хранение и восстановление

```text
userData/addons/
  registry.json
  packages/<id>/<sha256>.noctaddon
  storage/<id>.json
```

Сначала атомарно записывается неизменяемый пакет, затем переключается реестр.
При ошибке загрузки, подписи или записи предыдущий активный пакет сохраняется.
Хранятся указатели текущей и предыдущей версий, максимальная принятая ревизия,
включённость и отпечаток издателя. Откат сохраняет данные и не предлагает
повторно откатившуюся ревизию. Схема пользовательских данных должна сохранять
обратную совместимость с предыдущим выпуском — автоматического отката данных нет.
Старые файлы пакетов остаются до удаления расширения; автоматической очистки
истории нет. Удаление очищает файлы и собственное хранилище расширения.

Разрешения IPC доступны только главному фрейму окна Noctune. SDK-запросы старой
версии отклоняются после переключения версии. Ошибка одного расширения не
блокирует запуск других и воспроизведение локальной музыки.

## Настройки SDK 1

`manifest.settings` — объект до 32 полей. Ключ: латинская буква, затем буквы,
цифры, `_` или `-`, максимум 48 символов. Поля отображаются в карточке расширения
в **Настройки → Расширения → Настройки расширения**, работают и при выключенном
расширении, сохраняются отдельно от его произвольного `storage`.

```json
"settings": {
  "enabled": { "type": "toggle", "label": "Автосмена фона", "default": false },
  "name": { "type": "text", "label": "Название профиля", "default": "Мой профиль", "maxLength": 80 },
  "seconds": { "type": "number", "label": "Интервал, секунд", "min": 1, "max": 600, "step": 1, "default": 30 },
  "strength": { "type": "slider", "label": "Интенсивность", "min": 0, "max": 1, "step": 0.1, "default": 0.5 },
  "mode": { "type": "select", "label": "Режим", "default": "calm", "options": [{ "value": "calm", "label": "Спокойный" }, { "value": "bright", "label": "Яркий" }] }
}
```

Каждое поле может содержать `description`. Значения валидируются в main, числа
нормализуются по `step`; HTML не интерпретируется. При обновлении новые поля
получают default, несовместимые старые значения заменяются default. Текстовые
поля не предназначены для паролей и токенов: используйте защищённое хранилище.
`api.settings.get()` требует `settings.read`; `api.on('settings.changed', fn)` —
`settings.events`. Событие содержит `values` и `key` только своего расширения.

## Ресурсы, логотип и баннер

Ресурсы хранятся рядом с кодом, например:

```text
my-addon/
  manifest.json
  main.js
  assets/
    logo.png
    banner.jpg
    ui.woff2
    signal.ogg
```

В manifest можно указать необязательные поля:

```json
"icon": "assets/logo.png",
"banner": "assets/banner.jpg"
```

Это относительные пути к изображениям **внутри пакета**, не внешние URL.
Изображения показываются в установщике и в карточке установленного расширения.
Логотип лучше квадратный, баннер — широкий (примерно 4:1); размеры не обязательны,
интерфейс вписывает логотип и обрезает баннер через object-fit. Без изображений
остаётся обычная текстовая карточка; повреждённое изображение скрывается.

Поддерживаются PNG, JPEG/JPG, WebP, GIF, AVIF, ICO; шрифты WOFF/WOFF2/TTF/OTF;
аудио MP3/OGG/Opus/WAV/FLAC/M4A. JS/JSON/MD/TXT остаются UTF-8 строками.
Другие исполняемые форматы, HTML и SVG в ресурсах этого SDK не поддерживаются.
Упаковщик автоматически кодирует двоичные файлы в канонический base64:

```json
"files": {
  "main.js": "NoctuneAddon.define(api => { /* ... */ });",
  "assets/logo.png": { "encoding": "base64", "data": "iVBORw0KGgo..." }
}
```

Не нужно вручную готовить base64: используйте `scripts/pack-addon.cjs`.
Подпись пакета покрывает и двоичные ресурсы; подмена изображения нарушает подпись.
Ограничения — 2 МБ декодированных данных на ресурс, 16 МБ всего JSON-контейнера
с учётом base64 и 32 файла. Симлинки, абсолютные пути и `..` запрещены.

Доступ из Worker без дополнительных прав:

```js
const logo = api.assets.read('assets/logo.png'); // {mime, base64, size}
const dataUrl = api.assets.url('assets/logo.png');
const bytes = Uint8Array.from(atob(logo.base64), ch => ch.charCodeAt(0));
const defaults = JSON.parse(api.readText('assets/defaults.json'));
```

`readText()` не декодирует двоичные данные как UTF-8 и отклоняет такой запрос.
Наличие шрифта/аудиофайла в пакете не создаёт собственного окна или аудиоканала:
ресурсы доступны коду, а отображение logo/banner выполняет интерфейс Noctune.

## Разрешения SDK 1

[Полный справочник прав и границы API](extensions-permissions-v1.md) содержит
каждое действующее имя без сокращений и ограничения доступа. Ниже — краткая карта методов.

Каждая операция проверяется отдельно. Например, `themes.apply` меняет палитру
и параметры текущей темы, а `themes.switch` разрешает переключить саму тему.
Отдельное право `themes.accent` предоставляет `api.themes.accent({ color: '#ff6688' })`:
временный акцент поверх цвета текущей темы без изменения сохранённых настроек,
градиентов и параметров сцены. `{ color: null }` снимает только слой вызывающего
расширения. При отключении, удалении, обновлении или ошибке расширения слой снимается
автоматически. Из нескольких активных слоёв виден последний созданный; обновление
цвета не меняет приоритет. Изменения базовой темы под слоем сохраняются и становятся
видны после снятия слоя. Покадровые изменения акцента не рассылают `themes.changed`.
Не превышайте 20 обновлений в секунду и дожидайтесь ответа предыдущего запроса.
`themes.*` запрашивает все известные права этого раздела. Установщик показывает
права по раскрываемым группам: полный набор — одной строкой `[themes.*]` с
меткой «Полный доступ», частичный — жёлтой меткой «Частичный доступ · N/M».
Внутри перечислены только выданные права с полными системными именами и пояснениями.
Полнота определяется фактическим набором, поэтому перечисление всех прав по
отдельности тоже считается полным доступом. Новые права при обновлении отмечены
и у группы, и у конкретного пункта. **Конкретный набор прав фиксируется при установке**: новая
версия Noctune не выдаёт расширению новые права автоматически. Для получения
нового права нужен пакет с новой ревизией и согласие пользователя. Откат пакета
восстанавливает предыдущий набор прав. Каталог и подписи для UI находятся в
`src/shared/addon-permissions.js`; типы — в `addons/sdk.d.ts`.

| Разрешение | Метод / действие |
| --- | --- |

namespace, например `playback.pause`. Wildcard доступен для каждого namespace.
Управление и чтение не подразумевают друг друга; получение событий не разрешает действия.
События очереди/настроек не включают метаданные проигрываемого трека.

## События и асинхронные сценарии

```js
const unsubscribe = api.on('track.changed', async event => {
  const themes = await api.themes.list();
  if (themes.length) await api.themes.switch({ id: themes[0].id, sessionId: event.sessionId });
});
// unsubscribe() прекращает вызовы этого обработчика.
```

`api.on(type, handler)` принимает точное имя или группу `track.*` и т. п.
У каждого события есть `sequence` (растёт в рамках процесса renderer),
`timestamp` (Unix ms). События трека, воспроизведения и прогресса содержат:
`trackId`, `sessionId`, `title`, `artist`, `source`, `radio`, `playing`,
`position`, `duration`, `volume`, `speed`. Пути и подписанные CDN-ссылки не выдаются.
Идентификаторы локальных треков стабильны в текущем запуске и не заменяют
долговременный каталог сервиса. `source`: `file`, `radio`, `provider`.

- `track.changed` — выбран новый источник, ещё до получения метаданных и аудио;
  `track.metadata` — обновлены теги, длительность или название песни радио.
- `playback.play`, `.pause`, `.stop`, `.ended`, `.buffering`, `.error`, `.speed`,
  `.volume` — события медиа и управления. `stop.reason = stop-or-replace`;
  при ошибке есть `{error:{code,message}}`.
- `progress.updated` — примерно каждые 250 мс при воспроизведении; таймер может
  замедляться при сворачивании/сне. Для порогов сравнивайте позицию, не считайте тики.
  `progress.seek`, `.seeked`, `.duration` — перемотка и уточнение длительности.
- `queue.changed`, `playlists.changed`, `themes.changed`, `backgrounds.changed`;
  `settings.changed` и `settings.oauth` доступны только своему расширению.

Каждое новое воспроизведение, включая повтор той же песни, получает новый
`sessionId`; pause/resume, seek и смена названия песни радио его сохраняют.
События старого Audio игнорируются. После остановки текущий sessionId — null.
Передавайте sessionId в действие, зависящее от трека: просроченное действие
будет отклонено; переключение интерактивной темы проверяется также перед
показом подготовленного кадра. Не передавайте sessionId для намеренно глобальных
действий вроде ручного переключения темы командой.

Для каждого обработчика вызовы последовательны. Пока обработчик занят,
`progress.updated` объединяется до последнего значения; остальные события
хранятся в очереди до 16. Переполнение останавливает расширение с ошибкой.
Перемотка через порог может сработать на следующем progress; если действие нужно
один раз, заведите флаг на sessionId. Полный пример: `addons/examples/auto-appearance`.

## Очередь, плейлисты, оформление, звук

`playlists.read()` возвращает ID, названия, типы и известные локальные треки без
полных путей. Для папочных библиотек без открытого сканирования список может быть
неполным; выберите плейлист и запросите снова. Создание работает с файловыми
плейлистами внутри Noctune. Удалённые плейлисты обслуживает отдельный API `servicePlaylists`.
`edit({id,revision,tracks})` заменяет список существующими trackId; плейлист
с привязанной папкой и станции радио так не редактируются. Удаление активного
плейлиста останавливает его воспроизведение. Внешняя очередь ограничена 500
элементами; удаление и перестановка используют ID элемента, не индекс трека.

`themes.list()` выдаёт доступные интерактивные темы и схемы параметров;
`switch({id:null})` отключает текущую. `apply({parameters,palette})` использует
валидацию параметров сцены; палитра — `accent` и три цвета `gradient`, все #rrggbb.
Изменения параметров сохраняются существующим механизмом тем; акцент палитры
применяется в текущем сеансе. `backgrounds.list()` выдаёт встроенные и недавние
фоны через непрозрачные ID. `switch({id})`, `apply({enabled,fit,blur,threshold})`
используют штатный механизм оформления. `fit`: cover/contain/fill; числовые
границы blur/threshold совпадают с текущими контролами плеера.

`audio.analyse()` — FFT, байты 0…255; `audio.pcm()` — снимок float-сэмплов
текущего анализатора, вместе с sampleRate. Это не непрерывный поток PCM для
кодирования/записи. Не опрашивайте быстрее лимита 40 SDK-вызовов/с; рекомендуется
5–15 раз/с. Нет исполняемого AudioWorklet и произвольного DSP-кода в аудиографе.
`audio.equalizer({preset})` выбирает существующий пресет либо
`audio.equalizer({bands})` задаёт все полосы, −12…12 dB.
`audio.effects({chain})` добавляет до восьми узлов: gain (0…2), biquad (20…20000 Hz,
Q .01…30, gain −12…12 dB) и compressor (threshold −100…0 dB, ratio 1…20).
Цепочки нескольких расширений соединяются последовательно после штатного
панорамирования, не создавая параллельного необработанного выхода. Выключение,
ошибка или обновление расширения отключает его цепочку. `chain:[]` очищает её.

## OAuth и секреты

OAuth объявляется в manifest, не создаётся произвольным кодом в момент входа:

```json
"oauth": {
  "my-service": {
    "name": "Мой сервис", "flow": "authorization_code", "clientId": "PUBLIC-CLIENT-ID",
    "authorizationUrl": "https://accounts.example.com/authorize",
    "tokenUrl": "https://accounts.example.com/token",
    "scopes": ["music:read"], "resourceOrigins": ["https://api.example.com"]
  }
}
```

`resourceOrigins` должны входить в `network.origins`. Вход доступен кнопкой в
карточке расширения или `api.oauth.authorize('my-service')`; окно Noctune показывает
название расширения, сервер и scopes, затем открывается **системный браузер**.
Authorization Code использует PKCE S256, случайный state и локальный callback
`http://127.0.0.1:<port>/callback`, привязанный только к loopback. Порт обычно
динамический; необязательный `redirectPort` нужен сервисам с фиксированным URI.
Публичный desktop-клиент нужно зарегистрировать у сервиса с этим redirect URI;
client_secret не встраивается в пакет. Дополнительные параметры разрешены в
`extraParams`, но не могут подменить state/PKCE/clientId/redirect URI.

`flow: device_code` вместо authorizationUrl требует `deviceAuthorizationUrl`:
код показывается в штатном диалоге Noctune, браузер открывает verification URI,
брокер учитывает authorization_pending/slow_down и ограничение времени.
Оба сценария завершаются максимум через пять минут; выключение расширения
отменяет вход и закрывает loopback-сервер. Встроенных login-WebView нет.

Токены хранятся зашифрованно Electron safeStorage, отдельно для каждого ID
расширения. На Linux backend `basic_text` отвергается: без Secret Service/KWallet
вход недоступен, открытого JSON с токенами не создаётся. Refresh выполняется
автоматически перед запросом при истечении токена, параллельные refresh
объединяются. `invalid_grant` требует нового входа. Изменение clientId, scopes,
endpoint или ресурсных доменов в manifest делает прежнюю авторизацию
неактуальной. Выход удаляет локальный токен; серверный revoke пока не вызывается.
Удаление расширения очищает его зашифрованное хранилище.

`oauth.status()` возвращает только connected, secureStorage и expiresAt.
Worker не получает access/refresh token. Авторизованный запрос:

```js
const response = await api.network.request({
  url: 'https://api.example.com/me', oauth: 'my-service'
});
if (response.status === 401) { /* Предложить повторный вход. */ }
```

Bearer добавляет main только для точного resourceOrigin. При переходе на другой
origin заголовки авторизации не переносятся; тела POST не пересылаются на другой
origin. API никогда не считывает токены/куки официального приложения или браузера.
`secrets.get/set/delete` — отдельное пространство **собственных** секретов
расширения; эти методы не открывают доступ к OAuth-токенам. Ключи до 64 символов,
строки до 16000 символов, суммарно 128 КБ зашифрованных данных на расширение.

Шаблон: `addons/examples/oauth-client`; адреса example.com и clientId — заглушки.
Регистрация OAuth-клиента, допустимые scopes, доступность аудиопотоков и
лицензионные условия определяются конкретным сервисом.

## Сеть и музыкальные провайдеры

`network.request({url,method,body,headers,oauth})` поддерживает GET, POST, PUT,
PATCH, DELETE, HEAD. Возвращает `{status,headers,body}`; HTTP 4xx/5xx возвращаются
для обработки кодом интеграции, сетевые ошибки отклоняют Promise. Body — текст
до 64 КБ, ответ до 1 МБ. Заголовки требуют `network.headers`; Host, Cookie,
Authorization, Proxy-*, Sec-* и служебные заголовки подменять нельзя.
Авторизация идёт через поле oauth. Куки, локальные адреса и системный proxy
Chromium не используются. `text/json` остаются сокращениями для обычного GET.

```js
await api.providers.register({
  id: 'my-service', name: 'Мой сервис',
  search: async ({query}) => [{id:'track-123', title:query}],
  resolve: async ({trackId, reason, sessionId}) => {
    // Получить свежую ссылку по постоянному ID. reason: play или refresh.
    return {url:'https://cdn.example.com/track.mp3', oauth:'my-service', transport:'direct'};
    // Либо {error:{code:'REGION_RESTRICTED', message:'Недоступно в вашем регионе'}}.
  }
});
await api.providers.play('my-service', {id:'track-123', title:'Название', artist:'Исполнитель'});
```

Провайдер может добавить действия в контекстное меню собственных треков.
Укажите оба обработчика при регистрации:

```js
trackActions: async ({trackId}) => [
  {id:'like', title:'Нравится', icon:'Heart'},
  {id:'dislike', title:'Не нравится', icon:'ThumbsDown'}
],
trackAction: async ({trackId, action}) => { /* выполнить выбранное действие */ }
```

`trackActions` вызывается при открытии меню и только читает состояние. Результат
содержит до 16 действий с уникальным `id` (2–64 строчных букв/цифр/дефисов,
начиная с буквы), `title` до 120 символов и необязательным именем иконки Lucide.
Плеер отображает заголовки как текст. `trackAction` вызывается при выборе
пользователем, с исходным ID именно того трека, для которого открыто меню.
Одновременные действия одного трека блокируются; устаревшее меню нужно открыть
снова. После выключения или обновления расширения прежние действия недоступны.
Эти callbacks используют `providers.register`; сетевые изменения по-прежнему
требуют заявленных маршрутов и соответствующих разрешений.
Для горячих клавиш объявите отдельные команды в manifest и зарегистрируйте
их через `hotkeys.register({command})`. Команда выбирает текущий трек через SDK;
пункт меню относится к нажатому треку, даже когда играет другой.

Провайдер принадлежит расширению, search и resolve выполняются в его Worker.
`providers.search(provider,query)` возвращает до 100 результатов; универсального
поискового экрана в плеере пока нет — сценарий запускается командой расширения.
`providers.enqueue(provider,track)` добавляет в общую очередь и дополнительно
требует `queue.add`. Список треков провайдера появляется как временный плейлист;
плейлист и ссылки на поток не сохраняются на диск. Выключение провайдера
останавливает его активный поток, удаляет его очередь и временный плейлист.

URL разрешается main в непрозрачный `noctune-stream://audio/<handle>`. Основной
процесс проверяет публичный HTTPS, разрешённые origin, DNS, редиректы, выполняет
GET/HEAD и Range, затем отдаёт поток обычному Audio в основном renderer. Таким
образом работают штатные эквалайзер, громкость, анализатор и эффекты. CORS
удалённого сервера не мешает: междоменные запросы выполняет main, локальный
протокол отдаёт разрешённый аудиоответ, токены не появляются в URL Audio.
Ссылка и токены не записываются в плейлисты.

Нужен `network.request` и заявленные CDN-origin; для подключения bearer к CDN
он также должен быть resourceOrigin соответствующего OAuth-провайдера.
Поддерживаются прямые форматы, декодируемые Chromium (MP3, Ogg, WAV и т. п.).
DRM, проприетарные зашифрованные транспорты, HLS/DASH с отдельными сегментами
и скачивание для офлайна этим контрактом не реализованы.

На ошибке Audio выполняется **один** resolve с reason=refresh с сохранением
позиции и состояния паузы; повтор не превращается в бесконечный цикл. Смена
трека отменяет применение запоздавшего результата. Ожидание resolve — 20 секунд;
нет данных в активном HTTPS-потоке 30 секунд — ошибка. Классификацию серверных
причин выполняет адаптер: AUTH_REQUIRED, REGION_RESTRICTED, SUBSCRIPTION_REQUIRED,
NOT_FOUND, RATE_LIMITED, NETWORK, UNSUPPORTED_TRANSPORT. Политика backoff для 429,
региональные сообщения, availability и повторный вход принадлежат адаптеру;
настоящий геоблок и DRM обходить SDK не пытается. Диагностика приходит как
playback.error; исходные URL/токены в событие не включаются.

## Файлы и ОС

`files.select()` показывает системный выбор и возвращает `{handle,name,size}`;
`files.save()` выбирает файл для записи с подтверждением замены ОС.
`files.read({handle,encoding})` / `write({handle,data,encoding})`: utf8 или base64,
до 4 МБ. Handle привязан к ID и версии расширения, на каждую операцию проверяется
inode; символическая ссылка не подменяет уже выбранный файл. Запись разрешена
только handle, полученному через save. Пользовательские пути не передаются Worker.
`files.library({trackId})` разрешает выбранный известный трек из медиатеки, но для
чтения по-прежнему нужно `files.read`, а для reveal — `files.reveal`.

`system.openFile(handle)` открывает только разрешённые текстовые, графические
или аудиофайлы штатным приложением. Запуска shell, исполняемых файлов и доступа
к произвольным путям нет. `system.openExternal(url)` принимает HTTPS. Буфер
обмена ограничен 64 КБ текста. Все эти действия требуют отдельных разрешений.

## Локальные плейлисты: ревизии и вхождения

`read()` возвращает `revision` для каждого плейлиста и `entryId` каждого вхождения
в файловом плейлисте без привязанной папки. `trackId` обозначает известный локальный
трек, а `entryId` — конкретное вхождение, поэтому одинаковые треки различимы.
Эти идентификаторы и числовые ревизии действуют в текущем запуске.

```js
const playlist = (await api.playlists.read()).find(item => item.id === targetId);
const updated = await api.playlists.addTracks({
  id: playlist.id, revision: playlist.revision, tracks: [knownTrackId], index: 0
});
await api.playlists.removeTracks({
  id: updated.id, revision: updated.revision, entries: [updated.tracks[0].entryId]
});
```

`reorder({id,revision,entries})` принимает полный порядок ID вхождений.
`rename/delete/edit` также требуют текущую `revision`; `create/select` — нет.
При конфликте возвращается `REVISION_CONFLICT`: перечитайте состояние и предложите
новую операцию, не перезаписывайте свежие данные старым снимком. Право `edit`
остаётся массовой заменой состава. Добавление ограничено общим размером 10000 треков.

`playlists.changed` для локального изменения содержит `initiator` (ID расширения
либо null для штатного интерфейса) и массив `playlists: [{id,revision}]`.
Удалённая операция содержит `addonId/providerId/accountId/id/revision/initiator`.

## Каталог и плейлисты сервиса

`catalog.register({id,name,providerId,accountId,...callbacks})` регистрирует каталог
владельца. До восьми каталогов на расширение. `providerId` связывает аудиотреки с
собственным провайдером воспроизведения; каталог может работать без аудиопровайдера,
но тогда кнопки воспроизведения недоступны.

Callbacks:

- `browse({parent?,cursor?})` → `{items,cursor?}`. `items` до 100 объектов
  `{id,type,title,artist?}`, тип — `track/album/artist/playlist`.
- `search({query,cursor?})` → `{items,cursor?}` с теми же ограничениями страницы;
  используется встроенной строкой поиска в интеграции.
- `read({id?,cursor?,after?,reason?})` → страница `{items:[{id,name,revision}],cursor?}` либо,
  при указанном id, `{id,name,revision,tracks?,cursor?}`. Страница треков до 100
  элементов `{id,entryId,title,artist?}`; `entryId` уникален на странице.
- `create/rename/delete/addTracks/removeTracks/reorder(args)` →
  `{id?,revision,deleted?}`. Создание требует id результата; удаление — `deleted:true`.
  Новая ревизия должна отличаться от предыдущей. Noctune возвращает её строкой.

API вызова: `api.catalog.browse({catalog,parent?,cursor?})`,
`api.catalog.search({catalog,query,cursor?})`,
`api.catalog.unregister(id)`, `api.servicePlaylists.read({catalog,id?,cursor?,after?,reason?})`.
`unregister` удаляет каталог и его открытые списки при выходе или смене аккаунта.
Изменения используют свой метод:

```js
const playlist = await api.servicePlaylists.read({catalog:'my-library',id:'favorites'});
const requestId = 'rename-request-000001'; // Сохраняйте для повторения этой же операции.
await api.servicePlaylists.rename({catalog:'my-library',id:playlist.id,
  revision:playlist.revision, name:'Любимое', requestId});
```

У создания обязательны `catalog/name/requestId`, у переименования также
`id/revision`, у удаления `catalog/id/revision/requestId`. `addTracks` принимает
`tracks` — ID треков сервиса, а `removeTracks/reorder` — `entries`, ID вхождений.
До 100 элементов в одном запросе; полный порядок большого плейлиста требует
поддержки соответствующего сценария адаптером, текущий вызов ограничен 100.

SDK не вызывает неподдерживаемые callbacks. Права проверяются перед вызовом,
изменения одного плейлиста не выполняются параллельно. Noctune хранит до 500
результатов с requestId до остановки расширения; повтор с другими аргументами
отклоняется. Идемпотентность на сервере и после перезапуска реализует адаптер.
Отключение/обновление снимает каталоги; запоздалый результат не применяется к UI.

Начиная с Noctune 1.4.0 каталог интеграции размещается внутри её карточки в
«Настройки → Интеграции». Неизменяемые каталоги получают строку поиска,
обложки, карточки плейлистов и общий вид треков с контекстным меню.
Настройки подключения и дополнительные команды свёрнуты. Каталог без
`ui.integrations` остаётся в разделе расширений. Поддержка удалённых операций
создания/изменения сохраняется для каталогов с соответствующими callbacks.

Необязательные метаданные трека: `album`, `duration` (секунды, до 86400),
`canonicalId` (стабильный ID записи), `artwork` (публичный HTTPS-адрес до 2048
символов без userinfo, нестандартного порта и fragment). Плейлист принимает
`artwork`, `total` (целое 0…100000) и `continuous:true` для динамического потока.
Обложки получает брокер по разрешённым origins/routes с `network.request` и
`catalog.register`: без токена, OAuth, cookies или заголовков расширения,
только PNG/JPEG/WebP/GIF/AVIF до 512 КБ. Кэш ограничен и хранится в памяти.

Открытие конечного списка загружает до 300 треков; далее доступны дополнительные
страницы, общий предел — 10000. SDK по-прежнему возвращает максимум 100 треков
за callback. Сервисные списки имеют собственный тип и значок облака. Закрытие
такого списка не удаляет его на сервере. Сохраняется ссылка owner/catalog/account/id,
а не музыкальные данные или подписанные URL; при запуске список читается заново
после регистрации подходящего каталога.

При `continuous:true` плеер заранее запрашивает продолжение через `read` с
`reason:'continue'`, текущим `cursor` и `after` — opaque ID играющего трека.
`reason:'open'` означает первоначальное открытие. Адаптер возвращает новую партию
и следующий cursor; ревизия партии может меняться. `entryId` должен быть уникален
между партиями, `canonicalId` позволяет исключить ближайшие повторы. Плеер
добавляет новые треки, сохраняя текущий, и ограничивает историю потока 500 треками.
Автопереход учитывает общую настройку плеера. Ошибка продолжения отображается
пользователю; автоматического обхода ошибки возвратом к началу потока нет.

`settings.credentials` сообщает `{profile,configured}` после успешного изменения
профиля через штатную форму интеграции. Адаптер должен остановить свой поток,
снять старый каталог и повторно проверить аккаунт. Значение ключа не передаётся.
`playback.skip` с `reason:'next'|'selection'` обозначает явное действие пользователя;
автоматическое завершение трека остаётся `playback.ended`.

## Маршруты сетевых операций

Доступ к сети вместе с `servicePlaylists.*` требует `network.routes`:

```json
"network": {
  "origins": ["https://api.example.com"],
  "routes": [
    {"origin":"https://api.example.com","path":"/playlists/read","methods":["POST"],"permission":"servicePlaylists.read"},
    {"origin":"https://api.example.com","path":"/playlists/delete","methods":["DELETE"],"permission":"servicePlaylists.delete"},
    {"origin":"https://api.example.com","path":"/audio/","prefix":true,"methods":["GET","HEAD"]}
  ]
}
```

До 64 маршрутов. По умолчанию путь точный; `prefix:true` требует путь с `/` на конце.
Origin входит в `network.origins`; с 1.4.0 маршрут может использовать тот же
шаблон `https://*.cdn.example.com`. Неоднозначные кодированные разделители, точки
и повторное percent-кодирование в пути отклоняются. Query не участвует в сопоставлении пути.
Проверяется каждый redirect с его фактическим HTTP-методом, включая смену на GET
после 303. При нескольких совпадениях должны быть выданы все указанные права.
Ограничения действуют для `network.request`, `network.text/json` и аудиопрокси.
Профиль авторизации не снимает ограничений маршрута. Изменяющий GET или читающий
POST описывается в соответствии с реальным контрактом сервиса; Noctune не угадывает
смысл endpoint. Декларация маршрутов требует проверки при разработке адаптера.

## Панель интеграции и условные поля

Право `ui.integrations` разрешает следующий раздел manifest:

```json
"ui": {"integrations": {
  "title":"Мой сервис", "description":"Настройки подключения",
  "sections":[{"id":"connection","title":"Подключение","fields":["manual","endpoint"]}]
}},
"settings": {
  "manual":{"type":"toggle","label":"Ручная настройка","default":false},
  "endpoint":{"type":"text","label":"Профиль","default":"Основной",
    "visibleWhen":{"field":"manual","equals":true}}
}
```

До восьми разделов, без повторения полей. Нераспределённые поля идут после разделов.
`visibleWhen` поддерживает равенство строки/числа/boolean другой собственной настройке.
Скрытие не стирает значение и не изменяет выданные права. Кнопки берутся из `commands`,
вход — из `oauth`, ручные ключи — из `credentials`. Код не получает DOM/HTML/CSS.
Настройки находятся в интеграциях, а карточка расширения содержит переход к ним.

## Защищённые ручные ключи

```json
"credentials": {
  "api-key": {
    "name":"Ключ сервиса", "description":"API-ключ личного аккаунта",
    "origins":["https://api.example.com"], "header":"Authorization", "scheme":"Bearer"
  }
}
```

До восьми профилей. Допустим `Authorization` или заголовок `X-*`; `scheme` —
короткий префикс без пробелов, либо `""` для ключа без схемы. Нужен `network.request`;
точный origin профиля должен входить в `network.origins`; wildcard в профиле запрещён.

```js
await api.credentials.configure('api-key'); // Штатная форма; не принимает значение токена.
const state = await api.credentials.status('api-key');
const response = await api.network.request({url:'https://api.example.com/me',credential:'api-key'});
await api.credentials.disconnect('api-key');
```

Для этих операций нужны соответственно `credentials.configure/status/use/disconnect`.
Подстановка требует также `network.request` и права маршрута. OAuth и credential
не указываются вместе. Тело ключа не передаётся Worker, settings или главному
renderer: отдельная sandbox-форма отправляет его прямо main, который шифрует
значение в safeStorage. Можно указать срок действия. `status()` возвращает
`configured/secureStorage/expiresAt`, не ключ. Истёкший/изменившийся профиль требует
настройки заново. На Linux `basic_text` запрещён. Отключение закрывает форму;
удаление расширения очищает секреты. Выход пока локальный, без серверного revoke.
`StreamDescriptor` тоже допускает `credential` вместо `oauth`.

## Цветовые схемы интерфейса

Право `appearance.mode` → `mode({mode:'light'|'dark'|'system'|null})`.
`null` снимает свой выбор режима. `appearance.palette` → `palette({palette:object|null})`.
Разрешённые роли: `background`, `surface`, `text`, `muted`, `border`, `hover`,
`accent`, `secondary` (вторичный цвет исполнителя). Значения только `#RRGGBB`.
Пропущенные роли берутся из базовой light/dark схемы; пользовательский акцент
сохраняется, если его не переопределили. Проверяется читаемость основного текста.

```js
await api.appearance.register({id:'graphite',name:'Графит',mode:'dark',palette:{
  background:'#202024',surface:'#2b2b30',text:'#eeeeef',muted:'#b3b3bc',border:'#44444b'
}});
await api.appearance.switch({id:'graphite'});
await api.appearance.persist(); // Отдельное право; сохранить собственную копию.
```

`appearance.register` не включает схему. Она доступна пользователю в «Внешний вид»;
программный выбор требует `appearance.switch`. `{id:null}` снимает свой слой.
`appearance.read()` возвращает mode/effectiveMode, palette своего результирующего
стека и effectivePalette вычисленных CSS-ролей, включая временный акцент Chroma.
`appearance.events` разрешает `appearance.changed` (mode/effectiveMode).
До 128 схем на весь процесс. Имена и ID схем разделены по владельцам.

Временные слои снимаются при отключении/ошибке/обновлении. Последний созданный слой
выше предыдущих; обновление не меняет приоритет. Постоянное сохранение копирует
только собственный слой на пользовательскую базу и не захватывает другие временные
слои. Сохранённая копия независима от пакета и остаётся после его отключения.
Слой `themes.accent` всегда выше базового акцента оформления. Покадровые обновления
полной палитры не рекомендуются: для анимации только акцента есть `themes.accent`.

## Обложка, текст, режимы и горячие клавиши

- `artwork.read({sessionId?})` → `{sessionId,dataUrl,width,height}|null`, PNG до 256×256, без пути к файлу.
- `lyrics.read({sessionId?})` → `{status,lines,plain}` уже загруженного текста, без отдельного поиска.
  При закрытии панели или смене трека снимок очищается.
- `lyrics.provide({id,resolve})`: callback получает `{title,artist,album,duration,sessionId}`
  и возвращает `{status,lines,plain,source?}`. Для found максимум 3000 строк
  `{time,text}` в порядке времени; plain до 200000 символов. Время в секундах.
  Источники проверяются в порядке регистрации; missing/error/ошибка ведут к
  следующему и встроенному LRCLIB, instrumental означает отсутствие слов.
- `player.shuffle(boolean)`, `player.repeat(0|1|2)` — выключен/трек/плейлист.
  `player.current()` включает `shuffle/repeat`. Нужны отдельные права управления;
  `events.playback` разрешает `playback.shuffle/repeat` от штатного или программного изменения.
- `hotkeys.register({command})` добавляет объявленную команду в настройки горячих
  клавиш. Пользователь назначает сочетание. Расширение не получает события клавиатуры,
  не ставит системный перехват и не вызывает команды других расширений.

Полный рабочий пример: [Мастерская SDK 1](../addons/examples/service-workbench/README.md).

Для `appearance.mode/palette/switch` и чтения обложки/текста можно передать `sessionId`
в аргументах. Устаревший сеанс отклоняется; обложка дополнительно проверяется
после декодирования, чтобы запоздавшее изображение не попало к новому треку.

## Общие схемы, варианты настроек и временные обои

`appearance.list()` (`appearance.list`) возвращает встроенные `light`, `dark`,
`system` и схемы всех работающих расширений. Запись содержит `id`, `name`, `mode`,
`owner`; у внешней схемы также есть `schemeId` и человекочитаемый `provider`.
Её ID имеет вид `scheme:<addon-id>:<scheme-id>` и сохраняется между запусками.
`appearance.select({id})` (`appearance.select`) применяет выбранную схему в
собственном временном слое вызывающего расширения. `id: null` снимает этот слой.
Вызов явно поднимает его приоритет над другими слоями цветов; акцент Chroma
продолжает действовать поверх него. Настройки источника схемы не меняются.

`appearance.switch` по-прежнему выбирает только собственные схемы. При отключении
источника снимаются и временные слои, зависящие от его схем. Событие
`appearance.schemes` (`appearance.events`) сообщает об изменении списка. При
необходимости расширение заново запрашивает список и выбирает запасной вариант.

Штатный `select` может дополняться живым источником вариантов:

```json
"dayTheme": {
  "type": "select", "label": "Дневная схема", "default": "light",
  "options": [{ "value": "light", "label": "Светлая" }],
  "source": "appearance.schemes"
}
```

`source: "appearance.schemes"` требует `appearance.list`. `source: "backgrounds"`
требует `backgrounds.list`. Статические `options` и `default` обязательны; они
позволяют предложить встроенный режим или «Оставить текущие обои». Список
дополняется штатным интерфейсом и обновляется при изменениях источника, без
исполняемого кода в manifest. Исчезнувший выбор сохраняется, но показывается
недоступным; расширение само выбирает поведение при его отсутствии.

`backgrounds.list()` возвращает до 256 сохранённых и встроенных фонов. ID вида
`background:<sha256>` стабилен для пути между запусками; полный путь расширению
не выдаётся. До переключения или временной замены запросите список в текущем
сеансе. Доступность файла всё равно зависит от его наличия на устройстве.

`backgrounds.override({id})` (`backgrounds.override`) временно показывает выбранные
обои. `id: null`, остановка или ошибка расширения снимают только его замену.
После последнего слоя возвращаются сохранённые пользовательские обои и состояние
включённости; при необходимости возобновляется сохранённая интерактивная сцена.
Ручной выбор другого фона пользователем учитывается и не заменяется устаревшим
снимком при отключении расширения. `backgrounds.switch` остаётся обычным
сохраняемым переключением. Каталог обоев не даёт доступа к произвольным файлам.

## Плавное затихание собственного аудиослоя

`audio.gain({gain, ramp?})` требует отдельного `audio.gain`. Усиление — от 0 до 1,
`ramp` — длительность линейного перехода в секундах, от 0 до 300. Один узел GainNode
принадлежит одному расширению; последующие вызовы изменяют его автоматизацию,
без перестройки цепочки эффектов на каждом шаге. `gain: null` удаляет свой узел.

```js
await api.audio.gain({ gain: 0, ramp: 20 });
// Когда наступил срок таймера:
await api.player.pause(); // отдельно требуется playback.pause
await api.audio.gain({ gain: null });
```

Узел снимается также при остановке или ошибке расширения. Пользовательская
громкость, эквалайзер и чужие слои сохраняются. Время автоматизации связано с
AudioContext, поэтому таймер завершения расширение должно считать отдельно по
часам и учитывать возобновление приложения после сна.
