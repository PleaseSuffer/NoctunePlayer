# Локализация Noctune

## Файлы и идентификаторы

Каждый язык хранится в отдельном JSON-файле UTF-8:

- [ru_RU.json](../src/shared/locales/ru_RU.json) — русский.
- [en_US.json](../src/shared/locales/en_US.json) — английский (США).

Формат имени — `язык_РЕГИОН.json`. `en_US`, а не `en_EN`: `US` обозначает регион,
а `EN` не является кодом региона. `src/shared/locales/index.js` связывает файлы
с публичными кодами `ru` и `en`. В настройках, manifest и SDK используются BCP 47
коды с дефисом для региона: `en-GB`, `pt-BR`.

Содержимое файла — плоский объект «функциональный ключ → строка»:

```json
{
  "appearance.accent.label": "Цвет акцента",
  "equalizer.presets.bassBoost": "Усиление НЧ",
  "playback.repeat.playlist": "Повторять плейлист"
}
```

Ключ описывает область интерфейса, действие или назначение текста. Например,
`playback.repeat.off`, `playback.repeat.track`, `settings.player.autoRefresh.defaultInterval`.
Хеши и числовые идентификаторы для сообщений не используются. Оба базовых языка
содержат одинаковый набор ключей; файлы отсортированы по ключу.

## Загрузка и выбор языка

Выбор: **Настройки → Основные → Язык**, после блока «Производительность».
Язык сохраняется в `config.json`. Смена перезагружает окна и останавливает воспроизведение;
это указано рядом с dropdown. Исходный язык для установки без настройки — русский.

Главный процесс загружает JSON через `src/shared/locales/index.js`. Preload каждого окна
получает каталоги и начальный язык через проверяемый IPC `i18n:initial` и публикует
снимок в `noctuneLocale.initial`. Renderer не загружает JSON через сеть или `file://` fetch.
Это работает и в sandboxed окнах установки, магазина и ввода ключей. Смена языка через
IPC разрешена только основному окну; iframe и другие окна не могут менять настройку.

`src/shared/i18n.js` предоставляет:

- `t(key, args)` — текст с подстановками `{name}`.
- `html(key, args)` — текст и параметры, экранированные для HTML.
- `legacyHtml(key, args)` — экранирование шаблона с уже экранированными параметрами
  старых HTML-шаблонов. В новом DOM-коде используйте `textContent`.
- `register(owner, pack)`, `unregister(owner)` — реестр языковых пакетов.

Не вставляйте HTML в переводы. Набор параметров одного сообщения должен совпадать
между языками. Параметры принимают строки, числа и boolean. Неизвестные параметры
остаются в фигурных скобках. Отсутствующая строка использует базовый язык выбранной
локали, затем английский, затем русский; неизвестный ключ возвращается как текст ключа.

## Элементы интерфейса

`src/renderer/core/i18n.js` обрабатывает явные маркеры `data-i18n`, `data-i18n-title`,
`data-i18n-placeholder`, `data-i18n-aria-label`, `data-i18n-alt`.
`i18n-initial.js` переводит статические элементы до построения пользовательских dropdown.
Наблюдатель обрабатывает только помеченные элементы, а не пользовательские данные.

Названия треков, пользовательских плейлистов, пути, ID команд и значения настроек
не переводятся. Встроенные EQ-пресеты имеют стабильные идентификаторы и отдельные
переводимые подписи. Изменение языка не переименовывает сохранённые данные.

## Расширения и темы

[SDK расширений v2](extensions-api-v2.md) поддерживает перевод метаданных, сообщений
и регистрацию языковых пакетов. Переводы официальных расширений находятся в их
`locales/ru_RU.json` и `locales/en_US.json`; manifest содержит ссылки на эти файлы.
Текст стороннего расширения переводится его собственными словарями. API v1 совместим
с плеером и не получает объект `api.i18n`.

Темы API v2 поддерживают `manifest.localization` со встроенным `messages` для метаданных.
`parameterSchema.label` и подписи вариантов принимают строку либо словарь
`{ "ru": "…", "en": "…" }`. Порядок выбора подписи: точный язык, базовый язык,
английский, русский, первая доступная подпись. У тем и расширений отдельные версии SDK.

## Проверки

```powershell
npm test
node tests/run-electron.cjs tests/native-i18n-probe.cjs
node tests/run-electron.cjs tests/native-addons-probe.cjs
node tests/run-electron.cjs tests/native-official-extensions-probe.cjs
```

Альтернативный Electron задаётся полным путём в `NOCTUNE_ELECTRON`. Runner ожидает
завершения GUI-процесса и записывает stdout/stderr в `tests/.artifacts/native-logs/`.
Node-тесты проверяют ключи, полноту JSON, параметры, экранирование, владение языками,
изолированность IPC и сохранение исходного подписанного manifest.

После ручного изменения JSON-файлов перезапустите плеер: главный процесс загружает базовые каталоги при запуске.
