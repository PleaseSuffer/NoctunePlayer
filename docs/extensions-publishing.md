# Публикация расширений Noctune

Магазин открывается через **Настройки → Расширения → Магазин расширений**
в отдельном окне. Вкладка «Официальные» содержит каталог Noctune;
«Пользовательские» показывает заглушку каталога сообщества. Для просмотра
и установки расширений вход в GitHub не требуется.

## Что доступно сейчас

Из магазина устанавливаются опубликованные подписанные пакеты официального
каталога. Карточка без опубликованного пакета показывает «Скоро в магазине».
Перед установкой открывается окно с автором, подписью и разрешениями;
после установки расширение нужно включить в настройках.

Плеер получает каталог из
[репозитория Noctune](https://github.com/PleaseSuffer/NoctunePlayer/blob/main/addons/catalog/official.json).
При открытии сначала появляется сохранённая копия, затем выполняется проверка
GitHub. Без сети доступен последний корректный каталог либо копия из приложения.
Для повторной проверки есть кнопка «Обновить». Старый или повреждённый каталог
не заменяет уже сохранённую более новую копию.

Пользовательский пакет уже можно распространять напрямую: предложите скачать
`.noctaddon` и установить его из файла либо вставить HTTPS-ссылку на подписанный
пакет в настройках. Ссылка должна вести на сам файл, а не HTML-страницу релиза.

## Подготовка пользовательского расширения

1. Разместите исходники в публичном репозитории GitHub. Добавьте `manifest.json`,
   README с назначением и настройками, лицензию и контакт для сообщений об ошибках.
   Формат описан в [API расширений v1](extensions-api-v1.md).
2. Укажите стабильный ID, версию, положительную `revision`, совместимость,
   действительные ссылки и только необходимые
   [разрешения](extensions-permissions-v1.md). Объясните доступ к сети,
   авторизацию и хранение данных в README.
3. Создайте ключ издателя Ed25519 вне репозитория и сохраните резервную копию.
   Для всех обновлений одного расширения используется тот же ключ.
   Закрытый ключ, токены и пользовательские данные не входят в Git или пакет.
4. Соберите и подпишите пакет:

```sh
node scripts/create-addon-key.cjs /secure/path/author-private.pem
node scripts/pack-addon.cjs /path/to/my-addon ./my-addon-1.0.0.noctaddon --key /secure/path/author-private.pem
```

Первую команду выполняют один раз для создания идентичности издателя.
Путь `/secure/path/` — пример; выберите собственное защищённое расположение.
Официальный ключ Noctune для пользовательских расширений не используется.

5. Создайте релиз своего репозитория и загрузите `.noctaddon` как release asset.
   Опубликуйте версию, ревизию, минимальную версию Noctune, SHA-256 файла
   и отпечаток публичного ключа. Подпись определяет издателя пакета;
   имя автора и вход в GitHub сами по себе её не заменяют.
6. Для обновлений по сети подготовьте подписанный `release.json` тем же ключом:

```sh
node scripts/create-addon-release.cjs ./my-addon-1.0.0.noctaddon https://github.com/OWNER/REPOSITORY/releases/download/TAG/my-addon-1.0.0.noctaddon /secure/path/author-private.pem ./release.json
```

Стабильный адрес `release.json` указывается в `manifest.update.url` **до**
упаковки. Загружайте пакет первым, а сведения об обновлении — после него.
Проверка обновлений существующих установок не зависит от включения в магазин.
При любом изменении опубликованного пакета увеличивайте версию и ревизию;
не заменяйте содержимое опубликованной версии другим пакетом.

## Заявка в каталог сообщества

[Форма на GitHub](https://github.com/PleaseSuffer/NoctunePlayer/issues/new?template=extension-submission.yml)
собирает ID, исходники, ссылку на подписанный релиз, лицензию, контрольную сумму,
отпечаток издателя и описание разрешений. Отправка заявки не добавляет пакет
в приложение автоматически: каталог сообщества ещё не подключён.

Для рассмотрения нужны воспроизводимые исходники, соответствие пакета релизу,
понятное назначение, минимальные разрешения, отсутствие встроенных секретов
и корректная работа заявленных функций. Обновление с новыми правами или доменами
также требует явного согласия пользователя в установщике.

Пакеты остаются в GitHub Releases авторов; каталог хранит сведения о них,
SHA-256 и идентичность издателя. Исходники остаются в авторском репозитории.
Принятие в пользовательский каталог не делает расширение официальным.
Удаление карточки из каталога само по себе не удаляет уже установленный пакет.

## Формат официального каталога

`addons/catalog/official.json` — JSON формата `noctune-addon-catalog`,
`formatVersion: 1`, `channel: "official"`. Поля верхнего уровня:
`revision`, `generatedAt`, `entries`, `signature`. Каталог подписан Ed25519;
плеер принимает только доверенный ключ Noctune, встроенный в приложение.
Содержимое ограничено 4 МиБ и 64 карточками.

Карточка содержит метаданные manifest (`id`, `name`, `description`, `author`,
`type`, `version`, `revision`, `minNoctuneVersion`, необязательные
`maxNoctuneVersion` и `homepage`, `permissions`), а также:

| Поле | Назначение |
| --- | --- |
| `publisher` | SHA-256 отпечаток Ed25519 SPKI издателя пакета |
| `sha256` | SHA-256 точных байтов файла `.noctaddon` |
| `published` | Доступен ли пакет для установки |
| `packageUrl` | Прямая ссылка на asset GitHub Releases; обязательна для опубликованной карточки |
| `artwork` | Необязательные `icon` и `banner`: `{ "mime": "image/png", "data": "…base64…" }` |

Изображения могут быть PNG, JPEG или WebP; размер каждого base64-поля ограничен
1 МиБ. SVG и HTML не поддерживаются. Графика включена в подпись каталога и не
требует отдельных запросов к серверам авторов.

Официальные пакеты загружаются из Releases репозитория Noctune. Перед показом
установщика плеер проверяет SHA-256, подпись пакета, издателя и соответствие
метаданных карточке. Затем действуют обычные проверки совместимости, ревизии
и согласия на разрешения. Каталог не может самостоятельно запустить расширение.

GitHub поддерживает прямые ссылки на release assets и предоставляет их SHA-256
в API. Подробности: [документация GitHub Releases](https://docs.github.com/en/rest/releases/releases).
