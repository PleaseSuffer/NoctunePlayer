# Публикация расширений Noctune

## Автор и официальный издатель

Материалы, выпускаемые проектом в пользовательском разделе, указывают автора
`Noctune Community` — с заглавной C. Это относится к фанатским темам Rhodes Island
и Endfield и интеграции Яндекс.Музыки. Сторонние авторы указывают своё имя.

Официальные материалы проекта используют имя `Noctune`. В магазине галочка
определяется официальным разделом проверенного каталога, в установщике —
доверенной подписью пакета, а не строкой `author`.
Название `Noctune Community` само по себе не даёт
галочку или гарантию работоспособности. Подпись общего каталога подтверждает
целостность опубликованных пакетов, не меняя их пользовательский статус.

## Если закрытый ключ издателя потерян

Открытого ключа и старых подписанных пакетов недостаточно для восстановления
закрытого ключа. Для новых публикаций нужен новый Ed25519-ключ, хранящийся вне
репозитория, с отдельной резервной копией в выбранном владельцем защищённом месте.

Переход выпускается вместе с обновлением плеера: новый открытый ключ добавляется
к доверенным, старый сохраняется для проверки уже выпущенных пакетов. Старым
ключом больше не подписывают новые версии. Новый каталог можно подписывать
новым ключом после добавления доверия к нему в приложении.

Идентичность установленного расширения привязана к конкретному ключу, а не
только к имени Noctune. Поэтому обновления официальных расширений требуют
отдельного перехода со старого отпечатка на новый: ограниченного известными ID,
с явным согласием пользователя и повторной проверкой новых разрешений. Совпадение
имени издателя само по себе не разрешает такой переход. До реализации этого
перехода переподписывать существующие официальные расширения новым ключом нельзя.

Магазин открывается через **Настройки → Расширения → Магазин расширений**
в отдельном окне. Магазин содержит разделы «Расширения» и «Темы»,
в каждом — вкладки «Официальные» и «Пользовательские». Магазин тем также
открывается из настроек оформления. Для установки вход в GitHub не требуется.

## Что доступно сейчас

Из магазина устанавливаются опубликованные пакеты `.noctaddon` и `.noctheme`.
Карточка без опубликованного пакета показывает «Скоро в магазине».
Перед установкой открывается окно с автором, подписью и разрешениями;
после установки расширение нужно включить в настройках.
Для темы открывается штатное окно с превью; код сцены не выполняется при
просмотре карточки или установке. Установленную тему выбирают в оформлении.

Три темы Ноктилии находятся в `themes/official/<id>/` и загружаются отдельно:
их исходники и изображения не входят в установщик. Яндекс.Музыка находится в
`addons/community/yandex-music/` и публикуется как пользовательская интеграция.
Принадлежность к каталогу сообщества не означает гарантии работы сервиса.

## Темы и пользовательские расширения

Дополнительный индекс — `addons/catalog/marketplace.json`, формат
`noctune-marketplace`, версия 1. У каждой записи есть `kind` (`theme` или
`extension`) и `channel` (`official` или `community`). Пакеты находятся в
`addons/distribution/<id>/<version>/<id>-<version>.noctheme` или `.noctaddon`.
Адреса ограничены этим репозиторием; SHA-256 и метаданные сверяются до
открытия установщика. Опубликованный файл одной версии неизменяем.

```sh
./node_modules/.bin/electron scripts/publish-marketplace.cjs /secure/path/noctune-private.pem
```

Генератор сканирует только `themes/official`, `themes/community` и
`addons/community`. Каталоги `themes/user`, локальные эксперименты и настройки
пользователя никогда не сканируются. Миниатюры встроены в индекс; полные
изображения и скрипты загружаются только для установки выбранной темы.

Для подписанного пользовательского расширения поместите авторский релиз в
канонический путь `addons/distribution/<id>/<version>/<id>-<version>.noctaddon`
до генерации индекса. Генератор сохраняет подпись автора, если содержимое
без подписи точно воспроизводится из `addons/community/<id>/`. Закрытый ключ
автора для включения такого пакета в каталог не нужен.

Для подготовки нового встроенного снимка без доступа к ключу есть `--prepare`.
Такой снимок доверен как часть приложения; из сети разрешена только его
точная копия. Любые изменённые данные из сети или кэша требуют подписи
существующего доверенного ключа Noctune. Это не замена ключа и не разрешение
неподписанных обновлений. Старый подписанный `official.json` остаётся совместим
с выпущенными версиями плеера. Переход на подписанный индекс увеличивает ревизию.

Подпись индекса подтверждает выбранные куратором байты, а не работоспособность
дополнения. Подпись автора расширения проверяется отдельно. Совместимость с
уже установленной неподписанной Яндекс.Музыкой сохраняется: её пакет остаётся
неподписанным, это видно в окне согласия. Произвольные установки и обновления
по URL по-прежнему требуют подпись пакета. Обновления Яндекс.Музыки можно
проверять как на карточке магазина, так и штатной проверкой обновлений расширений.

Плеер получает каталог из
[репозитория Noctune](https://github.com/PleaseSuffer/NoctunePlayer/blob/main/addons/catalog/official.json).
При открытии сначала появляется сохранённая копия, затем выполняется проверка
GitHub. Без сети доступен последний корректный каталог либо копия из приложения.
Для повторной проверки есть кнопка «Обновить». Старый или повреждённый каталог
не заменяет уже сохранённую более новую копию.

Пользовательский пакет уже можно распространять напрямую: предложите скачать
`.noctaddon` и установить его из файла либо вставить HTTPS-ссылку на подписанный
пакет в настройках. Ссылка должна вести на сам файл, а не HTML-страницу релиза.

## Повторная публикация после восстановления каталога

Готовый подписанный каталог можно восстановить из истории Git только целиком,
без изменения содержимого. Клиенты, сохранившие более высокую ревизию, такой
откат не примут и продолжат использовать кэш.

Чтобы вернуть новые записи после восстановления, подпишите каталог актуальным
закрытым ключом и задайте ревизию выше всех уже опубликованных, включая
отозванные. Для этого генераторы поддерживают `--revision`:

```sh
./node_modules/.bin/electron scripts/publish-marketplace.cjs /secure/path/current-private.pem --revision 12
node scripts/publish-previews.cjs /secure/path/current-private.pem --revision 10
```

Числа приведены как пример: для каждого индекса выберите следующую свободную
ревизию. Она подписывается вместе с остальным содержимым; вручную менять JSON
после подписания нельзя. Без параметра генераторы используют обычное увеличение
ревизии. Повышение ревизии не разрешает менять содержимое пакетов или роликов
уже опубликованных версий.

Генератор магазина также запрещает менять издателя или канал пакета при прежней
версии. Используйте тот же актуальный ключ, которым подписан рабочий каталог;
случайный выбор прежнего доверенного ключа не должен приводить к публикации,
которую существующие клиенты отклонят.

## Официальные расширения из основного репозитория

Для официальных пакетов отдельный репозиторий и GitHub Releases не требуются.
Исходники находятся в `addons/official/<id>/`, подписанные пакеты — в
`addons/distribution/<id>/<version>/<id>-<version>.noctaddon`, а сведения для
магазина — в подписанном `addons/catalog/official.json`.

Из корня проекта запустите генератор с существующим закрытым ключом Noctune,
который хранится вне репозитория:

```sh
./node_modules/.bin/electron scripts/publish-official-addons.cjs /secure/path/noctune-private.pem
```

В Windows используйте `.\node_modules\.bin\electron.cmd`. Генератор использует
`nativeImage` Electron для миниатюр каталога; запускайте его в графической среде.
Он обнаруживает все папки с `manifest.json` в `addons/official/`, проверяет
пакеты, подписывает их, создаёт миниатюры и обновляет весь каталог. Новые
расширения добавляются автоматически. Повторный запуск без изменений не меняет
ревизию каталога. Опубликованные файлы не перезаписываются; изменение пакета
требует увеличения и версии, и ревизии. Удаление исходников не удаляет карточку
молча: генератор завершится с ошибкой, чтобы изъятие расширения было явным.

После проверки закоммитьте и отправьте пакеты вместе с каталогом. Пакеты загружаются
по прямым HTTPS-ссылкам `raw.githubusercontent.com`; разрешены только папка
`addons/distribution/` основного репозитория, ветка `main` либо полный SHA коммита.
ID, версия и имя файла в ссылке должны совпадать с карточкой. Ссылки на Releases
того же репозитория также поддерживаются.

Магазин показывает локальную копию сразу и проверяет актуальный каталог при
открытии, повторном открытии окна, нажатии «Обновить» и после установки.
Перед загрузкой пакета также проверяется свежесть каталога. Параллельные запросы
объединяются; автоматические повторные проверки используют результат до пяти
секунд. Явное обновление списка выполняет новый запрос. Ответы проверяются по
подписи, ревизии каталога и неизменности уже объявленных версий пакетов.

В настройках кнопки «Проверить обновление» и общей проверки используют тот же
каталог для всех установленных пакетов с доверенной подписью Noctune, включая
расширения без `manifest.update`. Для этого пути отдельный `release.json` не нужен.
Ошибки сети показываются как невозможность проверки, а не как отсутствие обновлений.
Найденное обновление устанавливается только после подтверждения пользователя;
новые разрешения остаются видны в установщике. Снятие карточки с публикации не
отключает и не удаляет уже установленное расширение.

## Подготовка пользовательского расширения

1. Разместите исходники в публичном репозитории GitHub. Добавьте `manifest.json`,
   README с назначением и настройками, лицензию и контакт для сообщений об ошибках.
   Формат описан в [API расширений v1](extensions-api-v1.md).
2. Укажите стабильный ID, версию, положительную `revision`, совместимость,
   действительные ссылки и только необходимые
   [разрешения](extensions-permissions-v1.md). Объясните доступ к сети,
   авторизацию и хранение данных в README.
3. Создайте ключ издателя Ed25519 вне репозитория и сохраните резервную копию.
   Для всех обновлений одного расширения используется тот же ключ.
   Закрытый ключ, токены и пользовательские данные не входят в Git или пакет.
4. Соберите и подпишите пакет:

```sh
node scripts/create-addon-key.cjs /secure/path/author-private.pem
node scripts/pack-addon.cjs /path/to/my-addon ./my-addon-1.0.0.noctaddon --key /secure/path/author-private.pem
```

Первую команду выполняют один раз для создания идентичности издателя.
Путь `/secure/path/` — пример; выберите собственное защищённое расположение.
Официальный ключ Noctune для пользовательских расширений не используется.

5. Создайте релиз своего репозитория и загрузите `.noctaddon` как release asset.
   Опубликуйте версию, ревизию, минимальную версию Noctune, SHA-256 файла
   и отпечаток публичного ключа. Подпись определяет издателя пакета;
   имя автора и вход в GitHub сами по себе её не заменяют.
6. Для обновлений по сети подготовьте подписанный `release.json` тем же ключом:

```sh
node scripts/create-addon-release.cjs ./my-addon-1.0.0.noctaddon https://github.com/OWNER/REPOSITORY/releases/download/TAG/my-addon-1.0.0.noctaddon /secure/path/author-private.pem ./release.json
```

Стабильный адрес `release.json` указывается в `manifest.update.url` **до**
упаковки. Загружайте пакет первым, а сведения об обновлении — после него.
Проверка обновлений существующих установок не зависит от включения в магазин.
При любом изменении опубликованного пакета увеличивайте версию и ревизию;
не заменяйте содержимое опубликованной версии другим пакетом.

## Заявка в каталог сообщества

[Форма на GitHub](https://github.com/PleaseSuffer/NoctunePlayer/issues/new?template=extension-submission.yml)
собирает ID, исходники, ссылку на подписанный релиз, лицензию, контрольную сумму,
отпечаток издателя (при наличии) и описание разрешений. Отправка заявки не
публикует пакет автоматически: запись и исходники добавляются после проверки.

Для рассмотрения нужны воспроизводимые исходники, соответствие пакета релизу,
понятное назначение, минимальные разрешения, отсутствие встроенных секретов
и корректная работа заявленных функций. Обновление с новыми правами или доменами
также требует явного согласия пользователя в установщике.

После проверки пакет размещается в `addons/distribution/`; каталог хранит сведения о нём,
SHA-256 и идентичность издателя. Исходники остаются в авторском репозитории.
Принятие в пользовательский каталог не делает расширение официальным.
Удаление карточки из каталога само по себе не удаляет уже установленный пакет.

## Формат официального каталога

`addons/catalog/official.json` — JSON формата `noctune-addon-catalog`,
`formatVersion: 1`, `channel: "official"`. Поля верхнего уровня:
`revision`, `generatedAt`, `entries`, `signature`. Каталог подписан Ed25519;
плеер принимает только доверенный ключ Noctune, встроенный в приложение.
Содержимое ограничено 4 МиБ и 64 карточками.

Карточка содержит метаданные manifest (`id`, `name`, `description`, `author`,
`type`, `version`, `revision`, `minNoctuneVersion`, необязательные
`maxNoctuneVersion` и `homepage`, `permissions`), а также:

| Поле | Назначение |
| --- | --- |
| `publisher` | SHA-256 отпечаток Ed25519 SPKI издателя пакета |
| `sha256` | SHA-256 точных байтов файла `.noctaddon` |
| `published` | Доступен ли пакет для установки |
| `packageUrl` | Прямая ссылка на пакет в `addons/distribution/` через GitHub Raw или на asset GitHub Releases; обязательна для опубликованной карточки |
| `artwork` | Необязательные `icon` и `banner`: `{ "mime": "image/png", "data": "…base64…" }` |

Изображения могут быть PNG, JPEG или WebP; размер каждого base64-поля ограничен
1 МиБ. SVG и HTML не поддерживаются. Графика включена в подпись каталога и не
требует отдельных запросов к серверам авторов.

Официальные пакеты загружаются из `addons/distribution/` либо Releases репозитория Noctune. Перед показом
установщика плеер проверяет SHA-256, подпись пакета, издателя и соответствие
метаданных карточке. Затем действуют обычные проверки совместимости, ревизии
и согласия на разрешения. Каталог не может самостоятельно запустить расширение.

GitHub поддерживает прямые ссылки на release assets и предоставляет их SHA-256
в API. Подробности: [документация GitHub Releases](https://docs.github.com/en/rest/releases/releases).

## Ротация издателя в текущей версии

Добавлен новый открытый ключ Noctune; прежний сохранён в `addons/official/publisher-legacy.json` и доверенных идентичностях плеера. Каталоги и официальные расширения 1.0.1 подписаны новым ключом. Старые опубликованные пакеты не изменяются. Обновите плеер перед установкой новых подписей.

Переход старого ключа на новый разрешён только для `noctune-chroma`, `noctune-dusk`, `noctune-shades`, `noctune-sleep`. Установщик показывает оба отпечатка и отдельное подтверждение смены ключа, помимо согласия на разрешения. При откате восстанавливаются прежняя подпись и набор прав. Для сторонних расширений и обратного перехода автоматической миграции нет.
