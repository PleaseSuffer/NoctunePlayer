## Процессы и ответственность модулей

`npm start` запускает `src/main/index.js`. Главное окно загружает `src/renderer/index.html`; системные API доступны интерфейсу через мост `window.noctune` из `src/preload/index.js`.

- **Main** управляет окнами, треем, обновлениями, Discord/Last.fm, сетевым получением текстов и обложек, дисковыми кэшами и настройкой аппаратного ускорения.
- **Preload** публикует разрешённые операции через `contextBridge`, читает файлы и метаданные, уменьшает обложки через `nativeImage`. Очередь ограничивает одновременную обработку; обложка активного трека получает приоритет.
- **Renderer** управляет интерфейсом и звуком через Web Audio API. Waveform строится отдельно от воспроизведения и хранится в компактном виде. Лимит FPS применяется к циклам эффектов, а прежний флаг `_rafSuspended` приостанавливает отрисовку при сворачивании в трей.

У главного окна включены `contextIsolation` и отключён `nodeIntegration`. `sandbox` отключён для preload, поскольку он использует Node.js для чтения файлов и метаданных. Изоляция контекста не означает, что preload работает в песочнице.

`src/web/redirect.html` публикуется отдельно от интерфейса приложения и обрабатывает переходы по ссылкам `noctune://`.

## Порядок загрузки renderer

Скрипты renderer подключаются обычными `<script>` и используют общие функции и состояние; это не независимые ES-модули. Источник актуального порядка — `src/renderer/index.html`.

1. В `<head>`: Lucide и `core/polyfill.js`.
2. После разметки: `core/dom-refs-state.js`, `core/effects-performance.js`, уведомления.
3. Фон, конфетти и фейерверки; затем управление воспроизведением, эквалайзер и плейлисты.
4. Waveform, общие обработчики перемотки (`playback/seek-controls.js`) и аудиодвижок; интерфейс текста, горячие клавиши и радио.
5. Визуализатор, `core/bootstrap.js`, настройки и настройки производительности.
6. Импорт/экспорт плейлистов и интерфейс обновлений.

При добавлении или переносе скрипта сохраняйте зависимости этого порядка. Например, `requestEffectsFrame` должен существовать до запуска циклов эффектов, а DOM — до инициализации элементов интерфейса.

## Хранение данных и кэши

| Данные | Расположение и срок жизни |
|---|---|
| Настройки, плейлисты, состояние, сессия Last.fm | `config.json` в каталоге Electron `userData`, через `electron-store` |
| Waveform на диске | `userData/waveforms/*.bin`; 200 байт пиков на файл, до 1000 записей, без учёта накладных расходов файловой системы |
| Waveform в памяти | До 60 записей с компактными пиками; полный декодированный аудиобуфер не сохраняется в кэше |
| Обложки локальных треков Last.fm | Кэш приложения, подпапка папки с музыкой либо выбранный каталог; настраиваемый лимит 10–300 МБ |
| Обложки радио | Текущая композиция в памяти; постоянный кэш обложек обходится |
| Тексты LRCLIB | Кэш main-процесса в памяти, до 200 записей; сбрасывается при завершении процесса |
| Миниатюры плейлиста | Изображения до 96 px; большая встроенная обложка активного трека извлекается отдельно, до 1024 px |

Путь `userData` определяется Electron для платформы и установленного приложения. Waveform проверяется по абсолютному пути, размеру и времени изменения аудиофайла; смена этих данных приводит к новому ключу кэша. Декодирование выполняется последовательно с частотой 8000 Гц; устаревшие задания не заменяют waveform текущего трека.

Настройка аппаратного ускорения читается синхронно до `app.whenReady()`. Изменение записывается в конфигурацию и требует перезапуска; переключение FPS применяется сразу.

## Запуск и упаковка

```bash
npm ci
npm start
npm run dist
```

`npm ci` устанавливает зависимости по lockfile. `npm run dist` запускает `electron-builder` для текущей платформы и сохраняет артефакты в `dist/`. Конфигурация содержит NSIS для Windows и AppImage, pacman, tar.gz для Linux. Сборки проверяются в соответствующей среде.

В пакет включаются `src/**/*`, `resources/app.ico`, `resources/app.png`, `package.json` и зависимости. Документация и тесты остаются в репозитории для разработки.

## Проверки

```bash
npm test
```

`tests/run.cjs` последовательно запускает файлы `.cjs` из `tests/main`, `tests/renderer` и `tests/structure`, останавливаясь при первой ошибке. Проверки включают кэширование, сетевые ошибки и отмену запросов, метаданные радио, переключение треков, миниатюры, память waveform, настройки GPU/FPS и связи файлов проекта. Проверки renderer используют изолированные сценарии Node.js; они не заменяют проверку интерфейса в Electron.

Отдельные сценарии настоящего Electron запускаются вручную. В PowerShell:

```powershell
.\node_modules\.bin\electron.cmd tests/native-memory-probe.cjs
.\node_modules\.bin\electron.cmd tests/native-thumbnail-probe.cjs
```

В Linux:

```bash
./node_modules/.bin/electron tests/native-memory-probe.cjs
./node_modules/.bin/electron tests/native-thumbnail-probe.cjs
```

Для этих сценариев нужна среда с графическим дисплеем. Они создают временные файлы и отдельный профиль, затем удаляют их. Проверка памяти сравнивает последовательное декодирование с исходным параллельным сценарием на синтетических четырёхминутных WAV; её показатели относятся к тестовым процессам и не отражают суммарную память всего приложения. Проверка миниатюр использует настоящие `nativeImage`, ленивую загрузку изображения и CSS приложения.
