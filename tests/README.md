# Проверки

Запускайте `npm test` из корня проекта. Сценарий выполняет файлы `.cjs` из
`main/`, `renderer/` и `structure/` и останавливается при первой ошибке.
Для запуска нужны Node.js и зависимости проекта. Графическая среда и настоящие
учётные данные сторонних сервисов не требуются.

| Группа | Что проверяется |
| --- | --- |
| `main/` | Проверка пакетов и подписей, разрешения и изоляция расширений, OAuth и защищённое хранение секретов, сетевые ограничения, кэши, установка тем, открытие файлов, системная интеграция и обновления |
| `renderer/` | Воспроизведение и перемотка, очереди, тексты песен, waveform, планирование эффектов, сохранение настроек, жизненный цикл SDK и работа официальных расширений |
| `structure/` | Точка входа, локальные импорты, ресурсы HTML и синтаксис JavaScript |

## Интеграционные проверки Electron

Эти сценарии проверяют взаимодействие настоящих процессов main/preload/renderer,
изоляцию браузерного контекста и API, которые нельзя проверить в сценариях Node.js.
Запускайте их последовательно из корня проекта в среде с графическим дисплеем:

```sh
./node_modules/.bin/electron tests/native-addons-probe.cjs
./node_modules/.bin/electron tests/native-service-library-probe.cjs
./node_modules/.bin/electron tests/native-metadata-sources-probe.cjs
./node_modules/.bin/electron tests/native-open-addon-probe.cjs
./node_modules/.bin/electron tests/native-addon-store-probe.cjs
./node_modules/.bin/electron tests/native-official-extensions-probe.cjs
./node_modules/.bin/electron tests/native-open-theme-probe.cjs
./node_modules/.bin/electron tests/native-mini-player-early-quit-probe.cjs
./node_modules/.bin/electron tests/native-scene-themes-probe.cjs
./node_modules/.bin/electron tests/native-scene-themes-probe.cjs --full-app
./node_modules/.bin/electron tests/native-playback-queue-probe.cjs
./node_modules/.bin/electron tests/native-playback-queue-timeline-probe.cjs
./node_modules/.bin/electron tests/native-playback-keep-awake-probe.cjs
./node_modules/.bin/electron tests/native-file-audio-options-probe.cjs
./node_modules/.bin/electron tests/native-tag-editor-probe.cjs
./node_modules/.bin/electron tests/native-tag-editor-probe.cjs --english
./node_modules/.bin/electron tests/native-settings-behavior-probe.cjs
./node_modules/.bin/electron tests/native-settings-toc-probe.cjs
```

В Windows используйте `.\node_modules\.bin\electron.cmd`.

Сценарии используют тестовые профили и сгенерированные данные. Снимки экрана и
сохранённые профили размещаются в `tests/.artifacts/`, исключённой из Git.
Проверки расширений используют временные ключи и подставные ответы сервисов;
настоящий вход в сторонние сервисы ими не проверяется. Проверка сервисной
библиотеки использует только фикстуру `fixtures/service-library-demo` и вымышленные
домены `.example`; она не зависит от стороннего расширения или музыкального API.

## Проверки установщика Windows

`.\node_modules\.bin\electron.cmd tests/native-windows-identity-probe.cjs`
проверяет раннюю установку идентификатора процесса и ресурсов панели задач у
окон. В том числе с `--app-asar=dist/win-unpacked/resources/app.asar` тест
сохраняет идентификатор разработки: запуск через стандартный Electron не
должен создавать ярлык Electron с идентификатором установленного Noctune.

```sh
node tests/native-installer-policy-probe.cjs
node tests/native-theme-associations-probe.cjs
```

Для запуска нужны инструменты NSIS, предоставляемые electron-builder. Сценарии
компилируют и выполняют тестовые примеры без установки приложения и изменения
системного реестра.

## Проверка собранного приложения

`npm run audit:package -- dist/linux-unpacked/resources/app.asar` проверяет состав
архива, импорты исполняемых модулей, ресурсы интерфейса, темы и обои.

Интеграционные проверки расширений принимают параметр
`--app-asar=dist/linux-unpacked/resources/app.asar` для запуска кода из сборки.
Проверка официальных расширений дополнительно принимает
`--official-packages=addons/packages` для проверки локально собранных подписанных
пакетов.

Контекстные действия провайдеров дополнительно проверяются в
`renderer/provider-actions.cjs`: привязка к выбранному треку, валидация ответа,
однократное выполнение, срок действия меню и отключение владельца.
`native-service-library-probe.cjs` проверяет динамические подписи лайка/дизлайка
и вызов зарегистрированной команды через назначенную горячую клавишу.

## Добавление регрессионных тестов

Добавляйте воспроизводимые проверки наблюдаемого поведения, публичных контрактов,
обработки ошибок и освобождения ресурсов. Постоянный тест должен иметь независимый
ожидаемый результат, изолировать свои данные и выявлять значимый сбой. Избегайте
дублирования существующих проверок и повторения деталей реализации. Не включайте
в репозиторий сеансы профилирования, сравнения с историческими реализациями и
снимки экрана, привязанные к отдельным выпускам.

`main/official-addon-publishing.cjs` проверяет обнаружение исходников, подготовку
подписанного каталога и пакетов в репозитории, неизменность опубликованных версий,
повторный запуск генератора, обновление через каталог с подтверждением пользователя
и поведение при ошибках сети. Используются временные ключи и тестовые ответы.


`main/addon-downloads.cjs` проверяет потоковое сохранение MP3 больше 4 МБ,
целостность байтов, имена и коллизии, MIME и оборванный ответ, подтверждение и
замену папки, отмену и отзыв доступа. `renderer/provider-action-cache.cjs`
проверяет кеш строк, объединение чтений, точечную инвалидацию, независимую
проверку действий меню, TTL и удаление кеша при отключении провайдера.


`main/error-reporter.cjs` проверяет очередь ошибок main до готовности интерфейса,
сохранение stack/code, проверку отправителя IPC и повторную загрузку окна.
`main/addon-network.cjs` также проверяет асинхронное завершение закреплённого DNS,
ENETUNREACH и ранние ошибки ответа/потока без необработанного исключения.

```sh
node_modules/.bin/electron tests/native-main-errors-probe.cjs
node_modules/.bin/electron tests/native-main-errors-probe.cjs --notifications-disabled
```

Проверка использует отдельный профиль, искусственные ошибки и подмену буфера
обмена внутри renderer. Она проверяет отсутствие нативных окон ошибок, toast,
полный копируемый stack trace, настройку уведомлений при запуске и во время
работы, ошибки открытия расширений. Поддерживает `--app-asar=...`.


`main/mini-player.cjs` выполняет проверки контроллера для `win32`, `linux` и
`darwin` на любой ОС. Платформа задаётся только локальной копии модуля, без
изменения глобального `process.platform`. Модель Windows передаёт прежние
координаты окна при движении курсора, Linux — событие `move` после перемещения,
macOS — предлагаемые координаты в `will-move`. Проверяются захват края,
удержание при небольшом движении, отлипание и сохранение конечной позиции.
Это проверки контроллера с макетами окон; нативное поведение ОС проверяется
отдельно в Electron.


`main/window-backend.cjs` проверяет выбор XWayland до создания окон, сохранение
аргументов при перезапуске, явные параметры запуска и отсутствие X11-дисплея.
`main/mini-player.cjs` дополнительно проверяет сохранение до отложенной записи
при скрытии и выходе, а также защиту сохранённой позиции от координат Wayland.

```sh
node tests/native-mini-player-position-probe.cjs
node tests/native-mini-player-position-probe.cjs --app-asar=dist/linux-unpacked/resources/app.asar
```

Сценарий запускается через Node, требует Linux с X11/XWayland и использует
отдельный профиль. Управляющий процесс ожидает также автоматически
перезапущенный Electron: проверяются нативное окно X11, два цикла
восстановления/сворачивания, запись позиции при быстром выходе и её восстановление
после следующего запуска. Нативное поведение Wayland сравнивается отдельно:
композитор определяет положение, а произвольное изменение параметра Ozone
в уже работающем процессе не считается успешным переходом на X11.


```sh
node_modules/.bin/electron tests/native-mini-player-opacity-probe.cjs --ozone-platform=x11 --disable-gpu
```

Проверка непрозрачности использует настоящий renderer и альфа-канал снимка окна
Linux, где нативный `setOpacity` не действует. Проверяются начальное значение,
живое изменение, наведение и уход курсора, изменение настройки под курсором,
повторное открытие и перезагрузка renderer. Наведение и уход доставляются через `webContents.sendInputEvent`, а глобальные
координаты намеренно остаются внутри окна. Дополнительно проверяется, что Linux
не опрашивает глобальный курсор. Тестовое окно игнорирует физическую мышь, чтобы
движения пользователя не влияли на результат; системная мышь и буфер обмена
пользователя не меняются.
Сценарий поддерживает `--app-asar=...`. В `main/mini-player.cjs` отдельно
проверяется нативная непрозрачность Windows/macOS и отсутствие двойного затухания.

## Надёжный запуск Electron на Windows

`native-addon-interface-probe.cjs` проверяет новые методы UI, уведомлений и
горячих клавиш через реальный Worker SDK: безопасный текст и прогресс,
закрытие своего уведомления, список и удаление своих команд, отдельные карточки
разрешений и очистку при отключении. Профиль и тестовое расширение изолированы.

`native-addon-store-probe.cjs` проверяет разделы тем и расширений, официальные и
пользовательские карточки, отмену и подтверждение установки `.noctheme` и
Яндекс.Музыки, прогресс и скорость загрузки, неизвестный размер файла, восстановление после ошибки, плитки NocStore и добавления темы из файла, обновление галереи, поиск и работу без сети.
Проверяются также постоянный размер кнопок, наследование оформления установщиками,
отклик обновления каталога, отмена и подтверждение удаления через оформленное
окно установщика, отключение активной темы.
Используется отдельный профиль и локальные ответы каталога; личные токены и
локальные экспериментальные темы не читаются.

Запускайте `node tests/run-electron.cjs tests/native-i18n-probe.cjs` (аналогично для остальных native-проб). Runner пишет вывод GUI-процесса в файл и ждёт завершения, исключая EPIPE от закрытого shell-пайпа. Альтернативный Electron задаётся через `NOCTUNE_ELECTRON`.

Проверки symlink на Windows пропускаются только при отсутствии права на файловые ссылки. Запрет directory junction и подмена обычного файла проверяются независимо.

## Анимированные превью магазина

`node tests/main/animated-previews.cjs` проверяет отдельный подписанный индекс
необязательных превью, ограничения загрузки, хеши, кэш, отмену и работу без сети.
`electron tests/native-animated-previews-probe.cjs` проверяет воспроизведение
через песочницу, плавный переход, статичный баннер при ошибке, клавиатуру,
режим уменьшения движения и освобождение ресурсов на локальных роликах.
Создание роликов и их доставка описаны в [документации превью](../docs/theme-animated-previews.md).

`renderer/playback-queue.cjs` проверяет общий порядок плейлиста и ручных добавлений,
независимость от просмотра другого плейлиста, перемешивание, повтор, очистку,
отмену проверки файла и добавление следующих страниц.
`native-playback-queue-timeline-probe.cjs` проверяет автоматическое заполнение панели,
управление очередью через SDK, реальное воспроизведение изменённого порядка,
возврат после вставки из другого плейлиста, прозрачность и цвета основного плеера,
отключение размытия, узкое окно и постепенную отрисовку большого плейлиста.
Поддерживает `--english` и `--app-asar=...`.

`renderer/queued-provider.cjs` проверяет сохранение коллекции и конкретного вхождения
сервисного трека, использование загруженных коллекций для SDK-очереди, пропуск
удалённых и недоступных треков, возврат к исходной очереди и отмену устаревших ошибок.
Проверяется также завершение попыток при полностью недоступном повторяемом плейлисте.
`native-queue-service-menu-probe.cjs` сравнивает основные действия, ширину, высоту строк
и иконки локального и сервисного меню, проверяет переход между источниками без
создания плейлистов, toast и продолжение после ошибки разрешения/удаления/обновления
потока, отсутствие названия источника в шапке очереди и размещение меню в узком окне.
Поддерживает `--english` и `--app-asar=...`.

`renderer/addon-notifications.cjs` проверяет контракт уведомлений SDK: права,
границы параметров, частичные обновления, команды и изоляцию ключей расширений.
`native-addon-interface-probe.cjs` также проверяет передачу новых параметров
и `notifications.update` через настоящий Worker.

```sh
node_modules/.bin/electron tests/native-notifications-probe.cjs --ozone-platform=x11 --disable-gpu
```

Проверка центра уведомлений использует отдельный профиль и подмену буфера обмена.
Она проверяет безопасный текст, прогресс, закрепление при переполнении toast,
копирование полного отчёта из истории, очистку, индикаторы, команды расширения,
остановку расширения и восстановление после перезагрузки renderer. Снимки двух
тем сохраняются в `tests/.artifacts/notifications/`.
