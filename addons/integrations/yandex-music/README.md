# Яндекс Музыка для Noctune · 0.3.0

Независимый адаптер неофициального API для SDK 1, Noctune 1.4.0+.

## Установка и подключение

```sh
node addons/integrations/yandex-music-tools/build.cjs addons/packages/yandex-music-0.3.0.noctaddon
```

Установите пакет через настройки расширений, включите его и откройте
**Настройки → Интеграции → Яндекс Музыка**. Нажмите «Подключить» и введите
личный OAuth-токен музыкального API без префикса OAuth. При обновлении поверх
0.2.0 профиль сохраняется; удалять расширение не нужно. После перезапуска
библиотека и открытые сервисные плейлисты восстанавливаются автоматически.

Токен вводится в защищённую форму самого Noctune. SDK хранит его через
safeStorage и подставляет Authorization только для api.music.yandex.net.
Расширение получает статус, а не значение ключа; обложки и CDN получают
запросы без токена. На Linux необходимо доступное Secret Service/KWallet.
Ручной токен не обновляется автоматически: истёкший ключ нужно заменить.
Инструкция по получению токена доступна в «Подключение и параметры» и открывает
[документацию библиотеки](https://ym.marshal.dev/token/) в системном браузере.
Публичный OAuth-клиент Noctune с доступом к music API не предоставлен.

## Библиотека и поиск

Вся работа с музыкой находится в карточке интеграции:

- «Мне нравится»: полная библиотека, метаданные через POST /tracks.
- «Мои плейлисты»: оригинальные списки аккаунта.
- «Сохранённые плейлисты»: в том числе списки других владельцев.
- «Персональные подборки»: плейлист дня и другие generatedPlaylists из /feed.
- «Моя волна»: динамическая очередь rotor user:onyourwave.

Поиск треков запускается при вводе или по Enter в одной строке. Результаты
показываются здесь же, с дополнительными страницами по кнопке.
При открытии конечного списка загружаются первые 300 треков, затем можно
добавлять по 300 до полного списка, максимум 10000. Нажмите «Открыть в плеере»
или выберите трек. Контекстное меню позволяет воспроизвести трек, поставить
следующим или добавить в очередь. В основном списке можно убрать отдельное
вхождение из текущего представления; это не удаляет трек из Яндекс Музыки.

Обложки плейлистов и треков берутся из coverUri/cover.uri сервиса, с размером
200×200, через ограниченный публичный брокер SDK. Сервисные списки имеют
значок облака и пометку «Сервис»/«Поток». Их можно закрыть в плеере;
оригинал на сервере сохраняется. На диске хранится только ссылка на открытый
список, привязанная к аккаунту. Музыка, ответы API и подписанные URL не сохраняются.

«Обновить библиотеку» перечитывает текущий раздел или плейлист.
Изменение настроек непрерывности применяется к следующей партии; включение
непрерывности у ранее открытого конечного списка требует повторного открытия волны.

## Моя волна и воспроизведение

Включённая по умолчанию «Непрерывная Моя волна» заранее получает следующие
рекомендации с queue текущего трека. Новые партии добавляются к списку,
сохраняя играющий трек; ближайшие повторы исключаются по стабильному ID.
История ограничена 500 треками. Общая настройка автоперехода плеера учитывается.
Недоступность API не запускает бесконечные повторы запросов или проигрывание
списка с начала: ошибка показывается пользователю, доступен ручной повтор.

Обратная связь Яндексу выключена по умолчанию. В параметрах можно включить
radioStarted, trackStarted, trackFinished и skip при явном переходе. События
отправляются только для треков, открытых из волны, с её batchId. Пауза,
перемотка и обновление URL не дублируют начало. Прослушанные секунды считаются
по прогрессу; скачки позиции не засчитываются. Очередь ограничена 24 событиями,
ошибка feedback не останавливает музыку. Сервер не гарантирует отсутствие
повторов и одинаковое поведение рекомендаций для разных аккаунтов.

resolve выбирает доступный полный MP3 ближайшего битрейта; preview и
зашифрованные потоки исключены. Подписанный URL строится по download-info,
включая шестнадцатеричный ts. CDN разрешаются общей декларацией поддоменов
SDK, без списка отдельных серверов. Повторный resolve обслуживает обновление
ссылки штатным плеером, включая сохранение позиции и паузы.

## Аккаунт и ошибки

Подключение и дополнительные команды свёрнуты в «Подключение и параметры».
При смене ключа или отключении через штатную форму SDK расширение снимает
старый каталог, останавливает собственный поток и проверяет новый аккаунт.
UID проверяется перед операциями, старые идентификаторы другого аккаунта
отклоняются. Серверное аннулирование токена при локальном выходе не выполняется.

Снимки конечных списков хранятся в памяти 10 минут, максимум 24, с ревизией и
уникальными ID вхождений; повторяющиеся треки в обычных плейлистах сохраняются.
Старый cursor отклоняется. 401 требует повторного входа; 403 отображается как
отказ доступа без угадывания причины. 429 учитывает Retry-After и общий cooldown.
Сеть/5xx требуют повторения действия. SDK ограничивает HTTP 15 секундами,
callback провайдера — 20 секундами; запоздалые результаты не применяются.

## Проверки

```sh
node addons/integrations/yandex-music-tools/test.cjs
npm test
node_modules/.bin/electron tests/native-service-library-probe.cjs --ozone-platform=x11 --disable-gpu
```

Изолированные проверки используют фикстуры API, подставной токен и настоящий
Chromium Audio: библиотека 720 треков, страницы 300/600, обложки, inline поиск,
контекстное меню, непрерывный переход между партиями волны. Настоящий аккаунт
проверен локальной диагностикой через защищённый брокер: две страницы
понравившихся, обложка, продолжение rotor, три MP3 CDN, HTTP 206 и перемотка.
Личные диагностические сценарии находятся в .development и не входят в пакет.

## Основания реализации

Локальный план .local/plans/yandex-music.md, docs/extensions-api-v1.md,
addons/sdk.d.ts и реализованный контракт SDK. Внешние первоисточники:

- [Методы yandex-music-api](https://github.com/MarshalX/yandex-music-api/tree/main/yandex_music/_client)
- [MP3 download-info](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/download_info.py)
- [Rotor и feedback](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/radio.py)
- [PKCE Яндекс ID](https://yandex.ru/dev/id/doc/ru/codes/code-url)

Наличие PKCE у Яндекс ID не подтверждает доступ к музыкальному API.
Адаптер не загружает сторонний код и не является официальным клиентом Яндекса.
Изменения неофициального API могут потребовать обновления расширения.
